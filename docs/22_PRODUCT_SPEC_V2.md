> 이 문서는 2026-08-04 서비스 기획 회의의 결정을 **구현 가능한 형태로** 옮긴 것입니다.
> 회의에서 나온 항목을 현재 코드와 하나씩 대조했고, 이미 되어 있는 것과 새로 만들

> - 상태: **불변조건 충돌 4건 결정 완료 (2026-08-04).** §11의 미결 6건이 남아 있습니다.
> - 수치의 단일 출처는 언제나 `src/constants/` 입니다. 이 문서와 코드가 다르면 코드가 맞습니다.
> - 상위 규칙은 [`AGENTS.md`](../AGENTS.md)이고, 이 문서가 그 규칙을 덮어쓰지 않습니다.

## 1. 이번 개정의 한 줄 요약

**상점을 빼고, 캐릭터·지도·방·PIP·AI 리포트를 제품의 다섯 기둥으로 세운다.**

기존 v1.1은 "자세 회복 → 괴물 공격 → 보상 → 상점"이 한 줄로 이어지는 구조였습니다.
V2는 보상의 종착지를 상점이 아니라 **캐릭터 성장과 학교 영토**로 옮깁니다.
포인트(잎사귀)의 소비처가 사라지므로, 경제 설계도 함께 바뀝니다(§6.4).

### C-01 경험치 감소 vs 레벨 퇴화 금지 — **결정: A**

| | 내용 |
|---|---|
| 회의 결정 | 중도 이탈·장시간 나쁜 자세·세션 미완료 시 **경험치 감소** |
| 기존 규칙 | `AGENTS.md` §2.5 — "자세가 흐트러졌다고 캐릭터가 이전 레벨로 퇴화하지 않습니다" |
| 왜 중요한가 | XP가 줄면 레벨이 내려갑니다. 현재 레벨은 `xpToStage(xp)` 로 XP에서 파생될 뿐 따로 저장하지 않기 때문입니다(`features/progression/growth.ts`). 즉 **XP 감소 = 레벨 퇴화**입니다. |
| 제품 관점 | 나쁜 자세를 벌점으로 다루면 "자세 자각과 습관 형성 피드백"이라는 제품 메시지가 "감시와 처벌"로 바뀝니다. 카메라를 켜 두는 제품에서 이 인상은 이탈로 직결됩니다. |

**결정 — A. XP는 감소하지 않는다. 주간 회복 지수를 신설한다.**

| 항목 | 내용 |
|---|---|
| 표시 위치 | 마이페이지 · AI 리포트 |
| 레벨 영향 | **없음.** XP·레벨과 완전히 분리한다 |
| 성격 | 주 단위로 오르내리는 상태 지표. 누적 점수가 아니다 |

**구현 요건**

- `FR-GRW-10` 주간 회복 지수는 `applyReward` 를 거치지 않는다. XP 경로와 섞이면 안 된다.
- `FR-GRW-11` 지수는 매주 월요일(KST) 다시 계산한다. 계산 창은 최근 7일이다.
- `FR-GRW-12` 지수는 **점수·등급·정상/비정상으로 표시하지 않는다** (`AGENTS.md` §2.4).
  "이번 주 회복이 지난주보다 잦아요" 같은 **변화 서술**로 보여준다.
- `FR-GRW-13` 지수 산출에는 회복 성공 횟수·세션 완주율·스트레칭 완료율만 쓴다.
  나쁜 자세 지속 시간은 쓰지 않는다 (`AGENTS.md` §2.3 · `D-015` 전송 금지 목록과 같은 이유).

> `FR-GRW-12` 가 중요합니다. 지수를 숫자 하나로 크게 띄우면 "자세 점수"와 구분되지
> 않습니다. 이 제품이 하지 않기로 한 바로 그 표현입니다.

### C-02 친구 자유 채팅 — **결정: B**

| | 내용 |
|---|---|
| 회의 결정 | 방에서 친구일 경우 **자유 채팅** |
| 기존 규칙 | `AGENTS.md` §10 — "자유 채팅 추가" 금지 |
| 현재 구현 | 고정 리액션 + 사용자 지정 응원 문구 3개(2~16자), `sanitizeReactionText` 로 검증. 자유 텍스트 없음 |
| 왜 규칙이 있었나 | 익명 로그인(계정 없음) 상태의 자유 채팅은 신고·차단·이용정지 수단이 없습니다. 대학생 대상 서비스에서 욕설·괴롭힘이 발생하면 대응할 방법이 없습니다. |

**결정 — B. 초대 코드로 들어온 방에 한해 자유 채팅을 허용한다.**

세 가지 안전장치가 **함께** 들어가야 합니다. 하나라도 빠지면 배포하지 않습니다.

| 요건 | 내용 |
|---|---|
| `FR-CHAT-01` | 채팅은 **초대 코드로 입장한 방에서만** 활성화한다. 랜덤 참여 방에서는 응원 문구만 쓴다 |
| `FR-CHAT-02` | 메시지마다 **신고 버튼**을 둔다 |
| `FR-CHAT-03` | 참가자 단위 **로컬 차단**을 지원한다. 차단하면 그 사람 메시지가 이후 보이지 않는다 |
| `FR-CHAT-04` | 메시지 길이는 **최대 80자**로 제한한다 |
| `FR-CHAT-05` | 채팅 기록은 **방이 끝나면 사라진다.** 서버에 보존하지 않는다 |
| `FR-CHAT-06` | 채팅 내용은 AI 리포트로 보내지 않는다 |

**`AGENTS.md` §10 개정이 필요합니다.**

```diff
- - 자유 채팅 추가
+ - 초대 코드로 입장하지 않은 방(랜덤 참여)에서의 자유 채팅
+ - 신고·차단·길이 제한 없는 자유 채팅
```

**신고 처리는 아직 정해지지 않았습니다.** 익명 로그인이라 제재할 계정이 없습니다.
1차는 **신고 로그 적재 + 로컬 차단**까지만 하고, 운영 대응은 후속으로 둡니다.
이 한계를 `docs/14_DATA_PRIVACY_SECURITY.md` 에 적어야 합니다.

## 3. 우선순위

### 3.1 회의 결정

| 구분 | 항목 |
|---|---|
| 먼저 | 지도(캠퍼스 영토전) · 성장 시스템 · PIP · 방 시스템 · AI 리포트 |
| 후순위 | 상점 (추후 개발) |

### 3.2 구현 순서 제안 — 회의 순서와 다릅니다

회의 순서를 그대로 따르지 않기를 권합니다. 이유는 **의존성**입니다.

- 캐릭터는 홈·성장·PIP·방·캠퍼스 **다섯 화면 전부**에 나옵니다. 레벨 체계가 6단계에서 15레벨로 바뀌면 다섯 화면이 전부 영향을 받습니다. 성장 시스템을 먼저 확정하지 않으면 나머지를 두 번 만들게 됩니다.
- 지도는 이번 개정에서 **가장 크고 가장 불확실한 작업**입니다(§7). 다른 것이 안정된 뒤에 착수해야 다른 기능을 막지 않습니다.

| 단계 | 내용 | 근거 |
|---|---|---|
| **0** | 상점 비활성화, 하단 탭·마이페이지 신설, 설정 정리 | 껍데기를 먼저 바꿔야 이후 화면이 제자리를 찾습니다 |
| **1** | 성장 시스템 (15레벨 · XP 곡선 · 성장 카드) | 다섯 화면의 공통 의존성 |
| **2** | 세션 생성 흐름 재구성 + 스트레칭 전/후 배치 | 사용자가 매일 지나는 경로. 지금 가장 어수선함 |
| **3** | PIP 2단계 (자세 색상·아이콘·화면 숨기기) | 기반이 이미 있어 증분이 작음 |
| **4** | 방 시스템 정리 (홈 진입 · 초대 코드 노출 · 캐릭터 표시) | 서버 구조는 이미 있음 |
| **5** | AI 리포트 마이페이지 축적 | 저장 경로는 이미 있음(§10) |
| **6** | 캠퍼스 지도 재설계 | 가장 크고 가장 불확실 |

> 담당이 나뉘어 있으므로 1·2·3(민철) 과 4(수현) 는 병행할 수 있습니다.
> 6(연우)는 §7.1 결정이 나오기 전까지 조사·프로토타입 단계로 둡니다.

### 6.5 상점 — 비활성화

**삭제하지 않고 기능 플래그로 끕니다.** 캠퍼스가 쓰는 방식과 같습니다.

- `VITE_ENABLE_SHOP=false` 를 추가하고, 꺼져 있으면 `/shop` 라우트를 **등록하지 않는다**.
- `storeItems.ts` · `progressionStore` 의 구매·장착 코드는 남긴다.
- 이미 구매한 사용자의 보유·장착 데이터는 지우지 않는다.

## 7. 캠퍼스 재설계

이번 개정에서 **가장 큰 작업**입니다. 현재 구현을 거의 쓰지 못합니다.

### 7.1 현재와 목표의 거리

| | 현재 | 목표 |
|---|---|---|
| 지도 | 12×8 = 96칸 **가상 캠퍼스** (강의동·도서관·광장·카페·잔디밭) | **서울 3D 위성지도** |
| 좌표 | 순수 격자. 지리 정보 아님 | 실제 지리 좌표 |
| 구역 | 자체 zone 5종 | 행정구역 또는 자체 Grid |
| 학교 | 10개 + 기타 | 서울 소재 대학 전부 |
| 시즌 | 14일 고정 | 분기 |

`campusMap.ts` 주석에 **"실제 서울 지도나 특정 학교 부지를 복제하지 않습니다"** 라고
명시돼 있습니다. 이 전제가 뒤집히는 변경입니다.

### 7.2 먼저 답해야 할 것

3D 위성지도는 **외부 지도 서비스 의존**을 뜻합니다. 지금까지 이 제품은 외부 런타임
의존이 Supabase 하나뿐이었습니다.

| 질문 | 왜 중요한가 |
|---|---|
| 어떤 지도를 쓰는가 | Mapbox · Google Maps Platform · Cesium · VWorld(국토부) 중 라이선스·비용·3D 지원이 다릅니다 |
| 비용은 얼마인가 | 대부분 월 지도 로드 수 과금입니다. 학생 프로젝트 예산 안에 들어와야 합니다 |
| 번들 크기는 | 3D 지도 라이브러리는 수백 KB~수 MB입니다. 현재 번들 예산에 영향을 줍니다 |
| 오프라인·저사양은 | 저사양 노트북에서 웹캠 추론 + 3D 지도를 동시에 돌릴 수 있는지 확인이 필요합니다 |
| 구역 단위는 | 서울 25개 자치구 / 대학 반경 그리드 / 임의 육각 그리드 |

> **권고 — 지도를 나중에 갈아끼울 수 있게 만듭니다.**
> 영토·기여도 로직은 지도 렌더러를 몰라야 합니다. `territory.ts` · `contribution.ts` 는
> 타일 ID만 다루고, 렌더러(`TerritoryMap.tsx`)만 교체하면 되도록 경계를 유지합니다.
> 지금 구조가 이미 그렇게 되어 있으므로, **로직을 건드리지 말고 렌더러만 바꾸는 것이
> 가장 싼 경로**입니다.

### 7.3 단계

| 단계 | 내용 | 사용자에게 보이는 것 |
|---|---|---|
| 1 | 지도 렌더링 | 서울 지도가 뜨고 내 학교 위치가 보인다 |
| 2 | 점수 반영 | 내 기여가 학교 점수로 합산돼 보인다 |
| 3 | 영토 시스템 | 구역이 학교 색으로 칠해진다 |
| 4 | 경쟁 요소 | 순위 · 뺏고 뺏기는 연출 |

회의에서 정한 순서 그대로입니다. **1단계 안에 사용자가 볼 수 있는 것이 있으므로**,
단계마다 배포할 수 있습니다.

### 7.4 시즌

| | 현재 | V2 |
|---|---|---|
| 길이 | 14일 고정 | 분기 (1·4·7·10월 1일 시작) |
| 초기화 | 시즌 종료 시 지도 리셋 | 동일 |
| 엠블럼 | 없음 | 시즌별 자체 제작 엠블럼 — 학교 색 + 자체 도형 (C-03 · `FR-CMP-20`~`23`) |

`season.ts` 의 `SEASON_LENGTH_MS` 고정 길이 계산을 분기 경계 계산으로 바꿉니다.
`campus_seasons` 테이블 행이 최종 기준이므로 마이그레이션이 함께 필요합니다.

### 7.5 학교 목록 확대

서울 소재 대학 전부로 늘립니다. 4년제만 해도 약 40여 곳입니다.

- 색상은 계속 **자체 컬러 프리셋**입니다. 공식 색상이라고 표시하지 않습니다.
- `CAMPUS_COPY.unofficialTheme` · `noLogo` 고지 문구를 그대로 유지합니다.
- 학교 수가 늘면 `SchoolPicker` 는 검색 + 박스 그리드가 되어야 합니다.

### 8.1 톤 전환 검토 — Zoom 계열

프론트엔드 담당이 **Zoom 디자인 토큰으로 전체 톤을 바꾸는 안**을 검토 중입니다.
클릭 가능한 프로토타입으로 만들어 봤고, 좌측 레일 4탭과 방 만들기 10단계가 들어 있습니다.

**왜 이 제품에 맞는가.** 친구 방은 사실상 화상회의입니다. 참가자 격자, 마이크 상태
배지, 하단 컨트롤 바, 빨간 종료 버튼 — 사람들이 이미 아는 조작 은유를 그대로
쓸 수 있습니다. 프로토타입은 **자세 상태 5종을 마이크 상태 자리에** 놓았습니다.

| 배색 | 아이보리 60 / 중립 30 / 파스텔 10 | 흰색·회색 바탕 + Blue 하나 + 의미색 3종 |

## 9. 구현 규칙 — AI 에이전트와 함께 작업하기 위한 것

이 제품은 사람과 AI 에이전트가 같이 만듭니다. 아래는 그 전제에서 나온 규칙입니다.

### 9.1 요구사항 ID를 쓴다

이 문서의 `FR-XXX-NN` 을 **커밋 메시지 · PR 설명 · 테스트 이름**에 그대로 씁니다.

```
feat: 세션 만들기를 5단계로 나눔 (FR-SES-01, FR-SES-02)
```

에이전트가 "무엇을 만들어야 하는지" 를 대화 기록이 아니라 문서에서 찾을 수 있게 됩니다.

### 9.2 수치는 `src/constants/` 에만 둔다

새 값도 예외가 아닙니다.

| 값 | 파일 |
|---|---|
| 레벨 15단계 · XP 곡선 | `constants/game.ts` |
| 회복 5분 / 10분 | `constants/session.ts` |
| 학교 목록 | `constants/campus.ts` |
| 방 인원 | `constants/rooms.ts` |

화면 코드에 숫자를 직접 쓰면 나중에 아무도 어디를 고쳐야 할지 모릅니다.

### 9.3 수용 기준을 E2E 테스트 이름으로 쓴다

각 `FR` 에 E2E 테스트를 1:1로 붙입니다.

```ts
test('FR-SES-05 — 세션 만들기에 과목·목표 입력이 없다', async ({ page }) => { … })
```

이번 세션에서 회귀 2건을 잡아낸 것도 E2E였습니다. **화면을 바꾸는 작업일수록 E2E가
유일한 안전망입니다.**

### 9.4 미완성 기능은 플래그로 격리한다

캠퍼스가 이미 이 방식입니다. 새 기능도 같게 합니다.

| `VITE_ENABLE_SHOP` | 상점 (기본 `false`) |

플래그가 꺼져 있으면 **라우트 자체를 등록하지 않습니다.** 주소로 들어와도 홈으로 보냅니다.

## 10. 이번 개정에서 **바뀌지 않는 것**

기획이 바뀌어도 아래는 그대로입니다. 새 기능을 만들 때 이 선을 넘지 않습니다.

1. 카메라 영상·프레임·랜드마크 좌표·개인 자세 기준은 **어떤 서버에도 보내지 않는다.**
2. 의료 판정·자세 점수·통증 예방을 **주장하지 않는다.**
3. 개인 기준 대비 **상대 변화**만 판단한다.
4. `away` · `unstable` 에서는 판정과 보상을 **멈춘다.**
5. 방에는 닉네임·참가 상태·게임 이벤트만 나간다. 자세 좌표·`bad` 상태는 나가지 않는다.
6. 보상은 `features/game/rewards.ts` `applyReward` **단일 경로**로만 지급한다.
7. 세션 종료는 `finalizeSession` **한 곳**에서만 확정한다.
8. 캠퍼스는 **표시·기여 전용**이다. 자세 판정·XP·난이도를 바꾸지 않는다.
