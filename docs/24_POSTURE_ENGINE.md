# 자세 판정 엔진 — 이식 문서

**이 문서는 다른 프로젝트로 옮기기 위해 쓰였습니다.** 픽셀 오픈월드로 방향이
바뀌면서 UpRight MVP에서 살아남는 것은 웹캠 자세 판정 기술과 그 주변 오픈소스뿐
입니다. 화면·게임·지도·디자인 시스템은 새로 만듭니다.

정확한 값은 언제나 코드가 정답입니다. 이 문서는 **왜 그렇게 되어 있는지**를
남깁니다 — 값은 코드에서 다시 읽으면 되지만, 이유는 잃으면 두 번 다시
복원되지 않습니다.

---

## 0. 한 줄 요약

정면 웹캠으로 **시상면(옆에서 봐야 보이는 앞뒤 움직임)** 을 잰다.
정면 카메라는 원래 그 축을 못 보므로, **정면에서도 보이는 대리 지표 여러 개**를
모아 투표시킨다. 절대 기준이 없고 **사람마다 캘리브레이션한 자기 기준**과
비교한다.

## 2. 왜 정면 카메라가 어려운가 — 이 프로젝트의 핵심 발견

거북목은 머리가 **앞으로** 나가는 것입니다. 그 이동은 카메라 렌즈를 향한 축을
따라 일어납니다. 정면 웹캠은 그 축을 정면으로 못 봅니다.

**초기 5개 축은 이걸 놓쳤습니다.**

- 3개(`lateralOffsetRatio`, `shoulderTiltRatio`, `torsoLean`)가 **좌우** 축이라
  앞뒤 이동과 무관
- 나머지 2개는 어깨너비로 정규화되는데, 머리가 앞으로 나오면 얼굴도 커지고
  어깨도 넓어져 **비율이 상쇄**

결과: 심한 거북목이 **bad 0%** 로 측정됐습니다.

### 왜 `forwardDepthRatio` 로 해결하지 않았는가

MediaPipe 랜드마크의 z 값이 있으니 그걸 주력으로 쓰면 될 것 같습니다.
**안 됩니다.** 코드 주석에 이미 경고가 있었습니다 — z 는 조명과 카메라 거리에
따라 흘러다닙니다. 캘리브레이션 시점과 세션 중반의 z 기준선이 달라져,
가만히 앉아 있어도 판정이 바뀝니다.

한 번 승격을 제안했다가 이 사실을 확인하고 **스스로 뒤집었습니다.**
`forwardDepthRatio` 는 `AUX`(보조)에 남기고, 대신 **흘러다니지 않는 축 4개**를
더했습니다.

### 더한 축 4개

| 축 | 원리 | 정규화 |
|---|---|---|
| `facePitchRatio` | 고개를 숙이면 얼굴이 세로로 단축되어 눈–코 간격이 벌어짐 | 눈 사이 거리 |
| `earEyeRatio` | 머리가 앞으로 나가면 귀가 눈보다 뒤로 처짐 | 눈 사이 거리 |
| `shoulderSpan` | 상체가 앞으로 말리면 어깨가 화면에서 넓어짐 | 없음 |
| `headDistanceCm` / `headPitchDeg` | Face Landmarker 의 4×4 변환행렬에서 직접 | cm · 도 |

**핵심**: 앞의 세 축은 전부 **정면에서 실제로 보이는 형태 변화**입니다.
깊이를 추정하지 않고 실루엣이 변하는 것을 잽니다. 그래서 조명에 흔들리지 않습니다.

머리 6DoF 두 축은 Face Landmarker 가 있을 때만 채워집니다. 없어도 나머지로
판정되고, **고개 숙임형 거북목은 그대로 잡힙니다.**

## 3. 파이프라인

```
웹캠 video
  → MediaPipe Pose Landmarker (full)      33점
  → MediaPipe Face Landmarker             478점 + 4×4 변환행렬
  → One Euro Filter                       점별 떨림 제거
  → features.ts                           11개 축 스칼라
  → classify.ts  votes()                  축별 이탈 점수
                 arbiter()                과반 투표 → good/warning/bad
                 step()                   HOLD 시간 만족해야 상태 전이
  → 화면 색 (초록/노랑/빨강)
```

**모든 단계가 브라우저 안에서 끝납니다.** 영상·프레임·랜드마크 좌표는 어떤
서버에도 가지 않습니다. 이 원칙은 새 프로젝트에서도 유지해야 합니다.

### 3-1. MediaPipe 설정 (`src/lib/mediapipe/loader.ts`)

```
Tasks Vision 0.10.35
Pose Landmarker  : full 모델, runningMode 'VIDEO', numPoses 2, GPU→CPU 폴백
Face Landmarker  : numFaces 1, outputFacialTransformationMatrixes: true
```

`outputFacialTransformationMatrixes` 가 핵심입니다. **이걸 켜야 머리 6DoF가
나옵니다.** 열 4개가 x/y/z 축과 평행이동인 column-major 4×4 행렬입니다.

GPU delegate 로 먼저 시도하고 실패하면 CPU 로 떨어집니다 — 학교 공용 PC에
GPU가 없는 경우가 실제로 있습니다.

### 3-2. One Euro Filter (Casiez 2012)

```ts
{ minCutoff: 0.8, beta: 0.01, dCutoff: 1 }
```

**왜 필요한가**: 새로 더한 비율 축들은 값이 작습니다(0.06 단위). 원본 랜드마크
떨림이 그 크기를 그대로 덮어버려, 필터 없이는 새 축이 전혀 작동하지 않았습니다.

**왜 One Euro 인가**: 이동평균은 지연이 생겨 빠른 자세 변화를 놓치고, 칼만은
과합니다. One Euro 는 **속도에 따라 차단 주파수를 바꿔** 천천히 움직일 때는
강하게 떨림을 죽이고 빠르게 움직일 때는 지연을 줄입니다. 딱 이 문제용입니다.

### 3-3. 판정 — 절대 기준이 아니라 자기 기준

사람마다 앉는 자세도, 카메라 위치도, 책상 높이도 다릅니다. **절대 임계값은
성립하지 않습니다.** 그래서 캘리브레이션으로 각자의 기준을 만듭니다.

축별 허용 오차:

```
tolerance = 민감도배수 × max(FLOOR[축], MAD[축] × 8)
이탈점수  = (현재값 − 중앙값) × 나빠지는방향 / tolerance
```

- **중앙값·MAD 를 씁니다. 평균·표준편차가 아닙니다.** 캘리브레이션 5초 안에
  기침 한 번 하면 평균이 통째로 밀립니다. 중앙값은 안 밀립니다.
- **`MAD_K = 8`** — MAD 는 표준편차보다 훨씬 작은 값이라 배수가 큽니다.
- **`FLOOR`** 는 바닥값입니다. 캘리브레이션 중 너무 가만히 앉아 MAD 가 0에
  가까우면 정상적인 미세 움직임까지 이탈로 잡힙니다. 그걸 막습니다.

`FLOOR` 값에도 이유가 있습니다. 좌우 비대칭 축(lateral·tilt·torso)은 바닥을
넓게(0.08~0.1) 뒀습니다 — 편하게 팔걸이에 기대면 캘리브레이션 정자세 대비
자연히 벌어지는데, 그건 거북목이 아니기 때문입니다. 숙임·접근 축은
좁게(0.03~0.06) 뒀습니다. **거북목 감지의 핵심이라 예민해야 합니다.**

머리 6DoF 두 축만 단위가 다릅니다(cm·도). `headDistanceCm: 4`,
`headPitchDeg: 8` — **4cm 접근 / 8도 숙임을 이탈 1.0** 으로 봅니다.

### 3-4. 히스테리시스

```
WARNING_ENTER = 1.0     이탈 1.0 넘으면 warning 진입
GOOD_EXIT     = 0.8     0.8 아래로 내려와야 good 복귀
BAD_STRONG    = 1.8     bad 판정선
```

진입선과 복귀선을 다르게 둡니다. 같으면 경계에서 색이 깜빡입니다.

`GOOD_EXIT` 은 원래 0.65 였습니다. 그러면 **0.65~1.0 사이에 자리 잡은 편안한
자세가 warning 에서 영영 못 빠져나오는 함정 구간**이 너무 넓었습니다. 0.8로
올렸습니다.

### 3-5. 시간 조건 (`HOLD`)

```
warning : 1500ms
bad     : 5000ms
good    : 2000ms
```

**순간값으로 색을 바꾸지 않습니다.** 물 마시려고 잠깐 고개를 숙인 것과
20분째 목을 빼고 있는 것은 다릅니다. 그 시간만큼 유지돼야 상태가 바뀝니다.

### 3-6. 민감도

```
gentle 1.4 / default 1.0 / sensitive 0.75
```

tolerance 에 곱합니다. 큰 값일수록 관대합니다.

## 4. 캘리브레이션 (`src/features/calibration/`)

```
FRAMING_MS         1500    프레임 안에 제대로 들어왔는지 먼저 확인
TARGET_MS          5000    실제 수집 시간
TIMEOUT_MS         20000   이 안에 못 끝나면 실패
MIN_VALID_SAMPLES  40      유효 표본 하한
BUCKET_COUNT       5       1초 구간 5개를 모두 채워야 함
```

**세 조건 전부 필요합니다.** 표본 40개가 2초 만에 쌓여도 5초 전에는 절대
완료하지 않습니다. 짧게 끝내면 그 순간의 자세만 기준이 되어, 세션 내내
어긋납니다.

구간(bucket)을 나눈 이유: 한 순간에 몰린 40개는 표본 1개나 마찬가지입니다.
5초에 고루 퍼져야 그 사람의 **평소 범위**가 잡힙니다.

### 프로필 버전

**현재 `version: 3`.** 버전 2 프로필은 새 축 데이터가 없어 조용히 무시되는데,
사용자에게는 "앱이 고장 났다"로 보입니다. 그래서 **강제로 재캘리브레이션**
시킵니다. 새 프로젝트에서 축을 또 바꾸면 반드시 버전을 올려야 합니다.

## 5. 검증 — `postureEval.spec.ts`

**합성 3D 자세로 파이프라인 전체를 돌리는 하네스입니다.** 임계값을 건드리기
전에 축 선택이 맞는지 먼저 증명하려고 만들었습니다.

케이스: 정자세 / 앞으로 이동한 머리 / 고개 숙임 / 좌우 기울기 / 얼굴 메시 없음.

**이게 이번 작업에서 가장 중요한 산출물일 수 있습니다.** 웹캠은 사람이 직접
앉아 봐야 확인되는데, 그러면 반복 검증이 불가능합니다. 이 하네스가 있으면
축을 바꿔도 회귀를 즉시 잡습니다. **새 프로젝트에 반드시 같이 가져가세요.**

## 6. 옮길 때 밟게 될 지뢰

### 6-1. 프리뷰 창에서는 카메라가 안 열립니다
Claude Code 의 Browser 도구는 `getUserMedia` 를 항상 거절합니다. **세션 화면
확인은 크롬에서 직접 열어야 합니다.** 아티팩트도 마찬가지입니다(iframe 제약).

### 6-2. `video.readyState < 2` 를 MediaPipe에 넣으면 조용히 실패합니다
빈 결과만 돌아옵니다. 카메라는 켜졌는데 영영 "측정 준비" 인 상태가 됩니다.
`play()` 가 resolve 된 뒤에 판정 루프를 시작해야 합니다.

### 6-3. 모델 파일이 42MB입니다
`public/mediapipe/` 로 자체 호스팅하면 저장소가 무거워지고, CDN
(`storage.googleapis.com`)을 쓰면 오프라인·CSP 환경에서 막힙니다. **아직
결정 안 난 사안입니다.** 새 프로젝트에서 다시 판단해야 합니다.

### 6-4. 숨겨진 탭에서 타이머가 스로틀됩니다
`setTimeout`/`setInterval` 로 시간을 재면 전부 1초 배수로 나옵니다.
HOLD 시간 계산은 **`Date.now()`/`performance.now()` 기준**으로 해야 합니다.

### 6-5. 축을 바꾸면 프로필 버전을 올려야 합니다
§4 참고. 안 올리면 옛 프로필이 조용히 무시되고 사용자는 원인을 모릅니다.

## 7. 절대 넘지 말아야 할 선 (새 프로젝트에도 그대로)

1. **영상·프레임·랜드마크 좌표는 어떤 서버에도 보내지 않습니다.**
   분석은 브라우저 안에서 끝냅니다. 서버로 나가는 것은 스칼라 집계뿐입니다.
2. **의료 판정을 하지 않습니다.** 진단·치료·통증 위험도를 말하지 않습니다.
3. **자세 점수·등급·정상/비정상 표시를 만들지 않습니다.**
   대신 회복 성공·감지 가능 시간·출석을 씁니다.
4. **AI 응답 금칙어는 런타임에서 막습니다.**
   `/진단|치료|처방|질환|통증|거북목|정상\s*자세|자세\s*교정/`
   — 걸리면 문장을 고치지 않고 **통째로 버립니다.** 부분적으로 지운 문장은
   뜻이 달라져 더 위험합니다.

> 참고: 3번과 픽셀 게이믹 요소는 충돌하지 않습니다. XP·레벨·퀘스트는
> **행동**(세션 완주, 회복 성공, 출석)에 붙이면 되고, **자세 자체를 점수화
> 하지만 않으면** 됩니다. 지금 MVP도 그렇게 되어 있습니다.
