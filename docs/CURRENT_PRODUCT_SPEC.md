## 1. 문제 정의

대학생은 시험·과제·코딩 작업에 몰입할수록 머리와 상체가 **자신의 편안한 기준에서** 벗어난 사실을 늦게 알아차립니다. 불편해진 뒤에야 자세를 고칩니다.

기존 도구가 실패하는 지점:

| 문제 | 사용자에게 생기는 결과 |
|---|---|
| 반복 경고·강제 팝업 | 기능을 꺼 버리거나 서비스를 이탈 |
| 획일적인 자세 점수 | 의료적 정상·비정상으로 오해 |
| 장소·카메라 높이 변화 | 잘못된 알림 → 신뢰 하락 |
| 혼자 쓰는 자세 도구 | 다시 켤 동기 부족 |
| 공부 게임과 자세 기능의 분리 | 이도 저도 아닌 경험 |
| 카메라 사용 | 영상 저장·전송에 대한 불안 |

UpRight Now 의 답: **점수가 아니라 회복 행동을 보상한다.**
흐트러짐을 지적하는 대신, 기준으로 돌아온 순간을 즉시 축하하고 게임 진행으로 연결합니다.

## 2. 타깃

**핵심 사용자** — 노트북으로 시험·과제·코딩·디자인 작업을 오래 하는 대학생

대표 페르소나:

- 22세 대학생, 하루 3~6시간 노트북 사용
- 도서관 → 기숙사 → 카페로 자주 이동
- 타이머 앱 사용 경험 있음, 자세 알림 앱은 경고 피로로 중단한 적 있음
- 카메라 영상 저장·공유를 걱정함
- 캐릭터 성장·친구와의 공동 목표·아이템 수집에 흥미

**대표 상황**

| 상황 | 목표 | 제약 | 제품 대응 |
|---|---|---|---|
| 도서관 시험공부 | 조용히 25분 집중 | 소리·큰 움직임 부담 | 도서관 프로필 · 앉은 스트레칭 우선 |
| 기숙사 코딩 | 흐름 오래 유지 | 장시간 몰입 | 내 공간 프로필 · 50분 옵션 · 2분 리셋 |
| 카페 과제 | 장소가 바뀌어도 안정 | 카메라·조명 변화 | 자리마다 기준 재등록 · 민감도 조절 |
| 2인 팀플 | 함께 완주 | 새 채팅은 불필요 | 친구 방 · 공동 보스 · 응원 3종 |

## 3. 핵심 가치

> **내 자세가 게임 컨트롤러가 된다.**

게임 버튼을 따로 누르지 않습니다. 실제 회복 행동만이 공격·성장·상점으로 이어집니다.

| 층위 | 가치 |
|---|---|
| 실용 | 개인 기준 기반 판정 · 장소마다 재등록 · 방해 적은 단계적 신호 · 세션별 회복 기록 |
| 감정 | 흐트러짐을 비난하지 않음 · 회복 순간 즉시 축하 · 6단계 캐릭터 성장 · 캠퍼스 아이템 |
| 사회 | 영상 없이 친구 상태 공유 · 공동 보스 · 기린 싱크 합동 공격 |

**하지 않는 것 (제품 불변조건)**

- 의료 진단·치료·통증 예방 주장
- 평균 자세 점수 · CVA 점수 · 정상/비정상 등급 표시
- 자세나 시선으로 집중 여부 추론
- 카메라 영상·프레임·랜드마크의 저장 또는 전송
- 친구에게 `bad` 상태·자세 좌표·나쁜 자세 시간 공개
- 자유 채팅 · 공개 자세 랭킹 · 결제 · 실제 학교 로고 무단 사용


## 6. 자세 기준

### 6.1 원칙

- **개인 기준 대비 상대 변화**만 판정합니다. 절대 각도·의료 기준을 쓰지 않습니다.
- 모든 2D 값은 **어깨 너비로 정규화**합니다. 고정 픽셀값을 쓰지 않습니다.
- 한 프레임으로 상태를 바꾸지 않습니다. 모든 전이는 지속 시간을 요구합니다.
- `visibility` 는 "보이는 정도"로만 쓰고 자세 정확도 확률로 해석하지 않습니다.

### 6.2 사용하는 랜드마크

MediaPipe Pose Landmarker 에서 9개 점만 사용합니다.

- **필수(core)**: 코 **또는** 양쪽 바깥 눈 + 양쪽 어깨
- **선택(optional)**: 양쪽 귀 · 양쪽 엉덩이 · z 좌표
  → 선택 항목이 없다는 이유만으로 측정 불가가 되지 않습니다(`limited` 로 계속 판정).

### 6.3 특징 6종

| 특징 | 의미 | 나빠지는 방향 | 구분 |
|---|---|---|---|
| `faceScaleRatio` | 눈 사이 거리 ÷ 어깨 너비 | 증가 (카메라로 접근) | 주 |
| `headHeightRatio` | 눈–어깨 세로 거리 ÷ 어깨 너비 | 감소 (고개 숙임·움츠림) | 주 |
| `lateralOffsetRatio` | 코가 어깨 중앙에서 벗어난 정도 | 증가 (좌우 기울기) | 주 |
| `shoulderTiltRatio` | 좌우 어깨 높이 차 | 증가 | 주 |
| `torsoLean` | 어깨 중앙 vs 엉덩이 중앙 좌우 차 | 증가 | 주 (엉덩이 보일 때만) |
| `forwardDepthRatio` | 코가 어깨보다 카메라 쪽인 정도 (z) | 증가 | **보조** |

`forwardDepthRatio` 는 **단독으로 warning·bad 를 만들지 않습니다.**

### 6.4 편차 계산

```text
tolerance = 민감도배수 × max( 축별 바닥값 , MAD × 8 )
deviation = max(0, (현재값 − 기준중앙값) × 나빠지는방향) ÷ tolerance
```

- **축별 바닥값** — 캘리브레이션 중 거의 움직이지 않아 MAD 가 0에 가까워도
  정상적인 미세 움직임이 이탈로 잡히지 않게 하는 하한입니다.
  (`faceScaleRatio` 0.05 · `headHeightRatio` 0.08 · `lateralOffsetRatio` 0.07 ·
  `shoulderTiltRatio` 0.06 · `forwardDepthRatio` 0.35 · `torsoLean` 0.08)
- **민감도 배수** — 부드럽게 1.4 · 기본 1.0 · 민감하게 0.75

### 6.5 프레임 투표

| 판정 | 조건 |
|---|---|
| `voteWarning` | 주 특징 1개 이상 deviation > **1.0** |
| `voteBad` | (주 특징 1개 이상 초과 **그리고** 주+보조 합계 2개 이상 초과) **또는** (주 특징 최대 deviation > **1.8** 그리고 품질 good) |
| `voteGood` | 사용 중인 모든 특징 deviation < **0.65** |

0.65 ~ 1.0 사이의 중간 지대에서는 후보를 지우고 현재 상태를 유지합니다(히스테리시스).
신뢰할 수 있는 **주 특징이 2개 미만**이면 판정을 중단하고 `unstable` 로 갑니다.

**모든 임계값은 프로토타입 조정값이며 의료 기준이 아닙니다.**
값 변경은 `src/constants/posture.ts` 와 `src/features/posture-engine/classify.ts` 에서만 합니다.

## 7. 캘리브레이션

`/calibration` — 이 자리·이 카메라에서의 편안한 자세를 등록합니다.

| 항목 | 값 |
|---|---|
| 목표 시간 | 5초 |
| 워밍업 제외 구간 | 앞 1초 (모델 예열) |
| 최소 유효 표본 | 40 프레임 |
| 특징별 최소 표본 | 30 프레임 (미달 시 그 특징은 기준에서 제외) |
| 실패 판정 | 12초 안에 표본 미달 → 자동 재시작 |
| 프레임 제외 조건 | 인물 미감지 · 얼굴/어깨 미감지 · 어깨 너비 과소 · 프레임 이탈 · 심한 얼굴 회전(yaw > 0.7) · 직전 대비 0.2 초과 급격한 움직임 |

나쁜 프레임은 **그 프레임만** 버리고 전체를 초기화하지 않습니다.

**저장 결과 (요약값만)**

```ts
{
  version: 2,
  id, name, createdAt,
  features: { [특징]: { median, mad, validSampleCount } },  // 원본 시계열 없음
  shoulderWidthMedian,
  deviceIdHash,                                            // 복원 불가 djb2 해시
  quality: { validSampleCount, meanVisibility }
}
```

평균이 아니라 **중앙값 + MAD** 를 씁니다(이상값에 강함).
`?postureDebug=1` 을 붙이면 랜드마크 오버레이가 표시됩니다(개발용).

## 8. 자세 상태

### 8.1 5종

| 상태 | 의미 | 화면 문구 |
|---|---|---|
| `good` | 기준에 가까움 | 편안한 기준에 가까워요. |
| `warning` | 조금 달라짐 | 자세가 조금 달라지고 있어요. |
| `bad` | 기준에서 벗어남 | 처음 등록한 기준으로 가볍게 돌아와 볼까요? |
| `away` | 인물 미감지 | 잠시 자리를 비웠어요. 돌아오면 측정을 이어갈게요. |
| `unstable` | 측정 어려움 | 측정하기 어려운 상태예요. 카메라 위치와 조명을 확인해 주세요. |

감지 품질은 별도로 `good` / `limited` / `unavailable` 로 표시합니다.
귀·엉덩이가 안 보이면 `limited` 로 **계속 판정**합니다.

색만으로 상태를 전달하지 않고 라벨·아이콘·문구를 함께 씁니다.

### 8.2 확정 규칙 (지속 시간)

상태 확정의 **유일한 소유자는 arbiter** 입니다.

| 목표 상태 | 필요한 연속 지속 시간 |
|---|---|
| `warning` | 1.5초 |
| `bad` | **5초** |
| `good` | 2초 |

짧은 프레임 누락은 마지막 신뢰 상태를 **800ms** 유지해 깜빡임을 막습니다.
인물 미감지가 **연속 8프레임** 이면 `away` 로 갑니다.

### 8.3 회복 사이클

```text
확정 bad 진입 (이미 5초 지속 검증 완료)
→ 즉시 회복 기회 시작            ← 여기서 5초를 다시 세지 않습니다
→ 회복 창 30초
→ good 이 연속 5초 유지되면 성공
→ 창을 넘기면 실패(recovery_missed)
→ 성공·실패 후 20초 냉각
```

- **이탈 시작부터 회복 기회까지 총 5초**입니다(중복 지연 없음).
- `away` · `unstable` 에서는 회복 창 시간과 good 유지 시간이 **동결**됩니다.
  실패로 처리하지 않고, 돌아오면 남은 시간부터 이어서 셉니다.
- 회복 기회를 놓쳐도 장기 XP 는 차감되지 않습니다. 현재 세션 콤보만 0이 됩니다.

### 8.4 파이프라인

```text
카메라 → usePoseDetection (~12fps, numPoses 2)
→ analyzeLandmarks (필수/선택 랜드마크 분리, 어깨 너비 정규화)

→ PostureGameBridge → gameStore(전투) + applyReward(보상) + 친구 방 reportRecovery
```

## 9. 개인 세션

### 9.1 길이

| ID | 집중 | 리셋 | 비고 |
|---|---:|---:|---|
| `25` | 25분 | 2분 | 기본값 |
| `15` | 15분 | 1분 | |
| `50` | 50분 | 5분 | |
| `demo` | 3분 | 1분 | 데모 — 기록·출석에 반영되지 않음 |

Supabase 스키마의 `duration_seconds` 체크 제약(180/900/1500/3000)과 일치시킵니다.

### 9.2 시간 규칙

- 세션 시간은 **시작 버튼을 누른 시점부터** 잽니다. 자세로 집중을 추론하지 않습니다.
- `away` · `unstable` 에서도 **타이머는 계속 흐르고 보상 판정만 멈춥니다.**
- 세 가지 시간을 분리 집계합니다: 세션 시간 / 감지 가능 시간 / 자리 비움 시간
- 자리 비움 60초 이상 → `계속하기` · `일시정지` · `세션 종료` 선택. **벌점 없음.**
- 일시정지·이어서 하기 지원.

### 9.3 종료와 완주 인정

`finalizeSession()` 이 **유일한 종료 진입점**이며 세션당 한 번만 실행됩니다.

| 종료 사유 | 완주 인정 | 결과 |
|---|---|---|
| 타이머 정상 종료 | ✅ | 기본 공격 + 완주 보상 + 출석 |
| 계획 시간 **80% 이상** 진행 후 수동 종료 | ✅ | 위와 동일 |
| 80% 미만 수동 종료 | ❌ | 기록만 남음. 보상·출석 0 |

데모 세션은 기록·출석에 저장되지 않습니다.

### 9.4 세션 화면 구성

- 사이드바를 숨긴 집중 레이아웃
- 왼쪽: 캐릭터(가장 큼) · 자세 문구 · 회복 콤보 · 마감괴수 체력
- 오른쪽: 남은 시간 · 이번 세션 집계(회복 성공/기회/획득 XP/잎사귀) · 제어 버튼
- 분석용 비디오는 우하단에 작게만 표시합니다(좌우 반전, 클릭 불가)
- 제어: 소리 · 미니 위젯 열기 · 스트레칭 예약 · 일시정지 · 세션 종료

## 10. 친구 세션 (2인 방)

### 10.1 흐름

```text
/room/new  방 만들기(이름·과목·목표·길이) 또는 6자리 코드 입장
→ 익명 로그인 → create_room / join_room RPC
→ /room/:code  대기실 — 참가자 2칸 · 초대 코드/링크 · 공동 보스 · 응원 3종
→ 두 사람 모두 "준비 완료" → 방장만 시작 가능
→ 각자 기기의 /session/room-:code 로 이동해 독립 분석
→ 성공 이벤트만 공유
```

### 10.2 공유하는 것 / 안 하는 것

| 공유 | 공유 안 함 |
|---|---|
| 닉네임 (최대 12자) | 카메라 영상·사진·프레임 |
| 참가 상태 (joining/ready/focusing/resting/away/completed) | 랜드마크·자세 좌표 |
| 캐릭터 성장 단계 | `bad` 상태·나쁜 자세 지속 시간 |
| 성공 이벤트 (회복·스트레칭·완주) | 개인 자세 기준·개인 점수 |
| 응원 3종 (조금만 더 / 같이 리셋하자 / 나도 완료했어) | 자유 채팅 |

`sanitizeRoomEvent()` 가 **허용 필드 6개(id·type·participantId·nickname·reaction·timestamp) 밖의
키가 하나라도 있으면 payload 를 통째로 버립니다.** 송신·수신 양쪽에 적용됩니다.

### 10.3 공동 보스

| 항목 | 값 |
|---|---|
| 공동 보스 최대 HP | 2000 |
| 회복 성공 | −40 |
| 세션 완주 | −100 |
| 기린 싱크 | −60 |
| 스트레칭 완료 | 방어막 +15 |

- **HP 의 최종 기준은 DB `rooms.boss_hp`** 입니다. 클라이언트가 덮어쓰지 않습니다.
- 변경은 `apply_room_damage` / `apply_room_shield` RPC 로만 원자적으로 이뤄지고,
  `room_events_processed.event_id` PK 가 중복 적용을 차단합니다.
- 서버측 상한: 피해 0~250, 방어막 0~50, 방 멤버만 호출 가능.

### 10.4 기린 싱크

- 서로 **다른** 두 참가자의 `recovery_earned` 가 **10초 이내**에 발생
- 아직 사용되지 않은 이벤트끼리 1:1 로만 짝지음 → 한 쌍당 1회
- 피해 호출에는 두 회복 uuid 를 **XOR 한 파생 id** 를 씁니다.
  두 클라이언트가 같은 값을 계산하므로 DB 가 정확히 한 번만 적용하고,
  원본 회복 id 와 겹치지 않아 dedup 테이블과 충돌하지 않습니다.
- 친구의 `bad` 상태를 추측하게 하는 문구를 쓰지 않습니다.

### 10.5 연결

- Presence: 준비·집중·자리비움처럼 느리게 바뀌는 상태
  (`participantId` 기준으로 dedupe — 최신 메타만 유지)
- Broadcast: 회복·스트레칭·완료·응원 같은 순간 이벤트
- 3초 폴링으로 `rooms` 행을 재조회해 postgres_changes publication 이 없어도 HP·상태가 따라옵니다
- 끊기면 30초 재시도 → 실패 시 `오프라인` 배지, **개인 세션은 계속**
- `realtime.messages` RLS 정책이 없어 표준(비 private) 채널을 사용합니다.
  방 데이터 자체는 테이블 RLS + RPC 검증으로 보호됩니다.

**미구현**: 방장 이탈 시 권한 이전, running 상태 늦은 입장 처리, 둘 다 완주 시 최종 필살기(`bothCompleted` 150 은 상수만 존재), 공동 결과 화면.

## 11. 게임 · 괴물

### 11.1 마감괴수 D-DAY

| 항목 | 개인 | 친구 방 |
|---|---:|---:|
| 최대 HP | 1000 | 2000 |

3단계 상태 표시:

| 단계 | HP 비율 | 라벨 |
|---|---|---|
| calm | > 60% | 과제지를 쌓는 중 |
| angry | 30~60% | 포스트잇을 뿌리는 중 |
| rage | ≤ 30% | 23:59 폭주 |
| defeated | 0 | 제출 완료 |

세션 중 보스를 직접 조작하지 않습니다. 회복과 완주가 자동으로 공격을 만듭니다.

### 11.2 행동 → 결과

| 현실 행동 | 게임 결과 | XP | 잎사귀 | 개인 보스 피해 |
|---|---|---:|---:|---:|
| 자세 회복 성공 | 특수 공격 | 30 | 10 | 40 |
| 세션 완주 | 기본 공격 | 100 | 100 | 100 |
| 스트레칭 완료 | 방어막 회복 | 20 | 20 | — |
| 목표 완료 자기보고 | 보너스 상자 | 20 | 20 | — |
| 두 사람의 가까운 회복 | 기린 싱크 합동 공격 | — | — | (방 −60) |

### 11.3 악용 방지 (단일 진입점)

- XP·잎사귀 적립은 **`applyReward()` 한 곳만** 통과합니다.
- 같은 이벤트 `id` 는 두 번 적용되지 않습니다.
- 회복 XP·포인트는 **세션당 최대 5회**까지만 적립됩니다(회복 횟수 자체는 계속 기록되고, 상한 도달 시 토스트로 알립니다).
- 보스 피해도 `eventId` 기준으로 중복 차단됩니다.
- 세션 종료는 `finalizeSession()` 한 곳만 — 중복 종료·중복 보상 불가.
- 같은 세션 id 를 재시작하면 종료 잠금과 회복 상한이 함께 초기화됩니다.

## 14. PIP (미니 위젯)

- **Document Picture-in-Picture API** 기반 별도 작은 창 (300×380, Chrome/Edge 116+)
- 설정에서 **세션 시작 시 자동 열기** 토글. 세션 화면의 `미니 위젯 열기` 버튼으로도 열 수 있습니다.
- 브라우저 정책상 사용자 제스처가 필요하므로 **시작 버튼 click 핸들러 안에서** 요청합니다.
- 오프너와 같은 JS 컨텍스트를 공유해 기존 store 를 그대로 구독합니다 — **별도 타이머·자세 엔진 없음.**
- 오프너의 스타일시트를 복사하고, 접근 불가(CORS) 시트는 link 로 복제합니다.

**표시 내용**: 캐릭터 · 남은 시간 · 자세 문구 · 회복 콤보 · 일시정지/이어서 · 원래 화면 · 닫기
**표시하지 않는 것**: 카메라 원본 영상 (PiP 문서에 video 요소가 존재하지 않습니다)

**실패 처리**

| 상황 | 결과 |
|---|---|
| API 미지원 | `unsupported` → 화면 안 미니 위젯 |
| 창 열기 차단 | `blocked` → 화면 안 미니 위젯 |
| 사용자가 PiP 창을 닫음 | 세션 계속 |
| 세션 완료·중단 | PiP 자동 닫힘 |
| 새로고침 | 자동 복원하지 않음 |

Media Session 의 `enterpictureinpicture` 핸들러도 등록합니다(지원 브라우저에서만, 미지원 시 조용히 무시).

## 15. 상점

`/shop` — 잎사귀 포인트로 캠퍼스 아이템을 구매·장착합니다.

- **잠금 해제 조건**: 첫 정상 세션 완주 (`shopUnlocked`). 그 전에는 안내 화면만 표시.
- **XP 와 잎사귀는 분리**된 통화입니다. XP 는 성장 전용, 잎사귀는 결제 전용.

| 종류 | 아이템 | 가격 |
|---|---|---:|
| 과잠 | 네이비 · 버건디 · 포레스트 · 코랄 | 각 100P |
| 백팩 | 새내기 · 도서관 · 팀플 | 각 80P |

- 과잠 1개 · 백팩 1개까지 동시 장착. 같은 아이템을 다시 누르면 해제됩니다.
- 중복 구매 차단, 포인트 부족 차단, 미보유 아이템 장착 차단 — 모두 store 레벨에서 처리합니다.
- 구매·장착 상태는 로컬에 저장되어 새로고침 후에도 유지됩니다.
- 실제 의상 이미지 레이어 전까지는 **색 리본 + 아이콘 배지**로 표시하고,
  `equippedJacketId` / `equippedBackpackId` 를 분리 유지해 나중에 이미지로 교체하기 쉽게 두었습니다.
- 실제 학교 로고·마스코트는 사용하지 않습니다.

### 17.1 결과 화면 `/result/:sessionId`

표시:

- 보스 전투 결과 (체력 바 + 몬스터 피해량)
- 학습 세션 시간 · **감지 가능 시간** · 자리 비움 시간
- 회복 성공 / 회복 기회 · 가장 빠른 회복 · 최고 콤보
- 획득 XP · 잎사귀
- 성장 타임라인
- 목표 진행도 자기보고 4단계 (완료 / 대부분 완료 / 절반 정도 / 조금 진행)
  → `완료` 선택 시 보너스 +20 XP / +20P (세션당 1회)

**표시하지 않음**: 평균 자세 점수 · CVA · 정상/비정상 등급 · 통증 위험 점수

### 17.2 기록 화면 `/history`

- 상단 집계: 완료 세션 수 · 총 세션 시간 · 감지 가능 시간 · 회복 성공 합계
- 세션 목록: 과목 · 시각 · 세션 시간 · 회복 횟수 · 획득 XP (중도 종료는 별도 표기)
- 주간 출석 캘린더

### 17.3 성장 화면 `/growth`

- 6단계 타임라인 · 현재 캐릭터 큰 미리보기 · 다음 단계까지 남은 XP · 최근 획득 XP 5건

### 17.4 출석

- 현재 구현: **완주한 세션이 있는 날**만 출석으로 표시합니다.
- 처벌형 연속 스트릭이 아니라 주간 캘린더 형태입니다.
- 계획 문서의 "10분 이상 진행 시 출석"은 **미구현**입니다
  (`ATTENDANCE_MIN_MS` 상수는 정의만 되어 있고 `markAttendance` 는 호출되지 않습니다).

## 18. 개인정보

### 18.1 데이터 경계

```text
[카메라 프레임] ── 브라우저 메모리에서 즉시 폐기 ──✗ 저장 ✗ 전송
      │
      └→ [특징 6종 수치] → [개인 기준 요약(median·MAD)] → localStorage
                                    │
                                    └→ [자세 상태 1개] → 화면
                                              │
                                              └→ [성공 이벤트만] → Supabase
```

### 18.2 원칙

- 모든 영상 분석은 브라우저 안에서만 수행합니다. 프레임은 처리 후 즉시 폐기됩니다.
- 카메라 영상·사진·프레임·랜드마크 원본 시계열을 저장·전송하지 않습니다.
- 얼굴 이미지를 저장소에 커밋하지 않습니다.
- 로컬에는 개인 기준 요약값과 세션 집계만 저장합니다.
- 카메라 `deviceId` 는 복원 불가능한 짧은 해시로만 저장합니다.
- 친구 방에는 닉네임·진행 상태·성공 이벤트만 전송하며, 허용 스키마 밖 payload 는 코드가 차단합니다.
- Supabase 는 RLS 활성화 + 익명 authenticated role, 서비스 역할 키를 프론트엔드에 넣지 않습니다.
- 회원가입·이메일·전화번호·비밀번호를 요구하지 않습니다.
- 의료 진단·치료를 제공하지 않으며, 불편이 지속되면 전문가 상담을 권합니다.

### 18.3 사용 금지 표현

`거북목으로 진단됐어요` · `정상 자세가 아닙니다` · `목 건강 점수 72점` ·
`통증을 예방합니다` · `AI가 집중하지 않는 것을 감지했어요`

### 19.1 로컬 (localStorage, 스키마 v2)

| 키 | 내용 |
|---|---|

| `upright-now:sessions` | 세션 요약 목록 |

  calibration 은 특징 스키마가 바뀌어 v1 기준을 폐기하고 재등록을 요구합니다(민감도는 유지).
- 저장 실패는 조용히 넘어가고 화면 값은 메모리에 유지됩니다.
