## 4. 자세 판정

### D-016 카메라 엔진 — MediaPipe Pose Landmarker 단일 런타임

- **대안** — TF.js MoveNet 을 자동 폴백으로 · OpenCV.js · Human · react-webcam
- **선택 이유** — 모델마다 좌표·신뢰도 의미가 달라서, 자동 폴백을 넣으면 **기존에 등록한 개인 기준이 다른 모델에서 무의미해집니다.** MoveNet + WASM 은 `?postureDebug=1` 에서만 도는 명시적 성능 진단으로 둡니다. react-webcam 은 기존 `useCamera` 의 권한·트랙 정지·기기 선택을 중복하고, OpenCV.js·Human 은 원본 프레임·얼굴 처리 범위와 번들 비용을 불필요하게 넓힙니다.
- **재검토** — 저사양 기기 관찰에서 Pose Landmarker 가 못 버티면 재검토.

### 프레임 품질 게이트

- **선택 이유** — 조도·대비·연속 프레임 변화를 32×24 캔버스에서 **브라우저 메모리로만** 계산하고, 품질이 부족한 프레임은 캘리브레이션 표본에서 제외합니다. 원본 프레임을 남기지 않으면서 나쁜 표본을 걸러내는 방법입니다.
- **재검토** — 없음.

### C-04 감지 민감도 — 설정 UI 제거, 내부값 `default` 유지 (2026-08-04)

- **회의 결정** — 설정에서 민감도 제거, 최대 민감도로 고정

- **재검토** — **R-01 실기기 관찰(사람 5~8명 · 카메라 3대 이상) 이후.** 이 항목이 지금 제품에서 가장 큰 미해결 위험입니다.

## 7. 인프라 · 개발 환경

### MediaPipe WASM·모델을 CDN 에서 받는다

- **대안** — 저장소에 담아 자체 호스팅
- **선택 이유(당시)** — 번들·저장소 크기를 줄이려고.
- **재검토 — 지금 필요합니다.** jsDelivr 와 `storage.googleapis.com` 두 곳이 **자세 감지의 단일 장애점**입니다. 그런데 저장소에는 `public/mediapipe/` 로 같은 파일 41.3MB 가 이미 들어 있고 **코드가 참조하지 않습니다.** 폴백으로 쓰든지(로더를 로컬 우선으로) 지우든지 정해야 합니다. 지금은 둘 다 아닌 상태로 배포마다 41MB 가 함께 나갑니다.

### Vitest 순차 실행 (`fileParallelism: false`)

- **증상** — 수집되는 spec 파일 수가 28/37/42/47/50 으로 매번 달랐는데 **종료 코드는 0** 이었습니다. 실패한 워커가 맡은 파일이 집계에서 조용히 빠졌습니다.
- **대안** — 워커 수 축소(3개로 줄여도 42/50 재현) · CI 로 이전
- **선택 이유** — 느려도(약 6분) 매번 전부 수집합니다. 추가로 `scripts/run-tests.mjs` 가 수집 개수와 디스크 spec 개수를 대조해 다르면 실패시킵니다.
- **재검토** — 더 빠른 머신으로 옮겨 재현되지 않으면 `fileParallelism` 만 되돌립니다. **가드는 남깁니다.**

### 배포는 항상 클라우드 빌드

- **선택 이유** — Vercel 환경변수가 sensitive 라 `vercel pull` 은 `[SENSITIVE]` 플레이스홀더만 받습니다. 로컬 prebuilt 를 올리면 깨진 번들이 배포됩니다.
- **재검토** — 없음.

### Zarafa 는 삭제가 아니라 이동

- **대안** — 완전 삭제
- **선택 이유** — `/landing`·`/zarafa` 라우트가 `public/zarafa-legacy/`(62MB)를 iframe 으로 띄우고 있었고, `public/` 은 그대로 `dist/` 로 복사되므로 배포마다 함께 나갔습니다. 지우는 대신 워크스페이스의 `zarafa-archive/` 로 옮겼습니다. **빌드 산출물 127MB → 65MB.**
- **재검토** — 없음. 복구 방법은 `zarafa-archive/README.md`.
