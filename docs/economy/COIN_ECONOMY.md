# 코인 경제 설계

기존 **잎사귀 포인트 · XP** 를 하나의 획득 표로 통합하고, 상점 구매 재화를
**코인** 하나로 정리합니다.

- 확정 수치의 실제 정답은 [`src/constants/coin.ts`](../../src/constants/coin.ts) 입니다.
- 이 문서의 시뮬레이션 표는 [`src/constants/coin.spec.ts`](../../src/constants/coin.spec.ts)
  가 검증합니다. 표를 고치면 테스트가 먼저 깨집니다.
- 기존 [`src/constants/game.ts`](../../src/constants/game.ts) 는 **건드리지 않았습니다**.
  적립 경로를 실제로 갈아끼우는 작업은 별도 PR 입니다.

관련 규칙: [AGENTS.md](../../AGENTS.md) §2.2(자세 점수 금지) · §2.5(성장 역행 금지),
[docs/14_DATA_PRIVACY_SECURITY.md](../14_DATA_PRIVACY_SECURITY.md)

---

## 1. 코인과 XP 의 관계

두 축을 하나의 획득 표로 묶되, **원장은 둘로 유지**합니다.

| | 코인 | XP |
|---|---|---|
| 뜻 | 지금 쓸 수 있는 잔액 | 줄어들지 않는 누적치 |
| 늘어나는 순간 | 획득 이벤트 | 같은 이벤트, 같은 양 |
| 줄어드는 순간 | 상점 구매 | **없음** |
| 하루 상한 | 300 적용 | 적용하지 않음 |
| 쓰는 곳 | 상점 | 성장 단계(`CHARACTER_STAGES`) |

XP 를 코인 잔액과 합치면 "옷을 사면 레벨이 내려간다"가 되어
AGENTS.md §2.5 (단계는 내려가지 않는다) 가 깨집니다. 그래서 **획득 규칙만 통합**하고
차감은 코인에만 일어나게 둡니다.

하루 상한도 코인에만 겁니다. XP 에 상한을 걸면 많이 한 날의 성장이 멈춰
"노력한 만큼 자란다"가 깨집니다. XP 는 상한 적용 **전** 값(`raw`)을 씁니다.

## 2. 획득 규칙 (확정)

| 항목 | 코인 | 조건 |
|---|---|---|
| 세션 진행 | **1분당 2** | 감지 가능한 시간만 셉니다 (§7 어뷰징 A1) |
| 자세 회복 성공 | **1회 5** | 세션당 5회까지 (`MAX_REWARDED_RECOVERIES`) |
| 세션 완주 | **+30** | 계획 길이 25분 이상 |
| 연속 출석 유지 | **하루 +10** | 그날 세션이 1회 이상일 때 |
| 하루 첫 세션 | **+20** | 하루 1회 |
| **하루 획득 상한** | **300** | 모든 원천 합산 |

스트레칭 보상 항목은 **없습니다**. 기능을 접기로 했습니다.
`REWARD.stretch` · `CONTRIBUTION_POINTS.stretch_completed` 는 전환 시 함께 제거합니다(§6).

### 세션 1회 = 얼마인가

```
세션 코인 = (감지 가능 분 × 2) + (인정 회복 횟수 × 5) + (25분 이상이면 30)
```

| 세션 | 회복 0회 | 회복 3회(표준) | 회복 5회(상한) |
|---|---|---|---|
| 15분 | 30 | 45 | 55 |
| 25분 | 80 | **95** | 105 |
| 50분 | 130 | 145 | 155 |

이 문서의 모든 시뮬레이션은 **25분 세션 + 회복 3회 = 95코인** 을 표준으로 씁니다.

## 4. 시뮬레이션

세 이용자 유형. 모두 25분 세션, 회복 3회, 연속 출석 유지 중으로 가정합니다.

### 표 A — 하루 획득량

| 유형 | 세션 코인 | 첫 세션 | 연속 출석 | 원 획득(raw) | 실지급 | 상한 |
|---|---|---|---|---|---|---|
| 가벼움 (1세션) | 95 | +20 | +10 | 125 | **125** | – |
| 보통 (2세션) | 190 | +20 | +10 | 220 | **220** | – |
| 열심 (3세션) | 285 | +20 | +10 | 315 | **300** | ⚠️ −15 |

회복을 매 세션 5회까지 하는 열심 유저는 raw 345 → 실지급 300, **−45** 가 증발합니다.

### 표 B — 단일 목표 저축 (다른 구매를 하지 않을 때)

며칠째에 살 수 있는지.

| 목표 | 가벼움 (125/일) | 보통 (220/일) | 열심 (300/일) |
|---|---|---|---|
| 첫 옷 (200) | 2일 | 1일 | 1일 |
| 첫 캐릭터 알 (800) | 7일 | 4일 | 3일 |
| 시즌 한정 (1500) | 12일 | 7일 | 5일 |
| 레어 알 (2000) | **16일** | 10일 | 7일 |

### 표 C — 순차 구매 (옷 → 일반 알 → 레어 알)

누적 목표액 200 → 1,000 → 3,000.

| 목표 | 가벼움 | 보통 | 열심 |
|---|---|---|---|
| 첫 옷 | 2일차 | 1일차 | 1일차 |
| 첫 캐릭터 | 8일차 | 5일차 | 4일차 |
| 레어 캐릭터 | **24일차** | 14일차 | 10일차 |

### 표 D — 30일 누적

| 유형 | 7일 | 14일 | 30일 | 30일에 살 수 있는 것 |
|---|---|---|---|---|
| 가벼움 | 875 | 1,750 | 3,750 | 옷 1 + 일반 알 1 + 레어 알 1 = 3,000 (잔액 750) |
| 보통 | 1,540 | 3,080 | 6,600 | 위 + 시즌 한정 1 + 옷 2 = 4,900 (잔액 1,700) |
| 열심 | 2,100 | 4,200 | 9,000 | 위 + 레어 알 1 + 옷 4 = 7,700 (잔액 1,300) |

## 5. 밸런스 문제 지적

> 수치는 지시대로 유지했습니다. 아래는 문제 제기와 대안입니다.

### 문제 1 — 하루 상한 300 이 3세션째를 갉아먹는다 (중간)

3세션 유저의 raw 는 315(회복 최대 시 345)라 **세 번째 세션의 마지막 15~45코인이 사라집니다.**
"더 했는데 안 준다"는 체감이 가장 나쁜 구간이고, 하필 가장 열심인 이용자가 맞습니다.

- **대안 a** — 상한을 **350** 으로. 3세션 유저를 정확히 담고, 4세션째부터 감쇄합니다.
- **대안 b** — 상한을 300 으로 두되 **완주 보너스(+30)만 상한 밖**으로. 완주는 명확한
  성취라 잘리면 가장 억울합니다. 상한은 "시간 파밍"을 막는 게 목적이므로 목적에도 맞습니다.
- 권장: **b**. 상한 숫자를 안 바꾸면서 체감 문제만 없앱니다.

### 문제 2 — 50분 세션이 25분 2회보다 손해다 (큼)

| | 코인 |
|---|---|
| 50분 1회 (회복 5회 = 세션 상한) | 155 |
| 25분 2회 (회복 5회 × 2세션) | **210** |

완주 보너스(+30)와 회복 상한(5회)이 **세션 단위**라, 길게 앉을수록 손해입니다.
긴 집중을 권하는 제품인데 보상은 잘게 쪼개라고 말합니다.

- **대안** — 완주 보너스를 길이 비례로: 25분 +30 / 50분 +60 / 15분 +15.
  회복 인정 상한도 25분당 5회로(50분 세션 = 10회). 기존 `sessionCompletionReward()`
  가 이미 길이 구간별 표라 구조도 그대로 재사용됩니다.

### 문제 3 — 시간 보상이 회복 보상을 압도한다 (중간)

표준 25분 세션 95코인의 구성: 시간 50 (53%), 완주 30 (32%), **회복 15 (16%)**.
카메라 앞에 앉아 있기만 해도 80코인, 자세를 잘 되돌린 보람은 15코인입니다.
"자세 회복"이 제품의 핵심 행동인데 보상 비중이 가장 낮습니다.

- **대안** — 분당 1코인 + 회복 8코인 (25분·회복 3회 = 25 + 24 + 30 = 79).
  시간 32% / 완주 38% / 회복 30% 로 균형이 맞습니다. 대신 전체 획득량이 17% 줄어드니
  가격도 같이 내려야 합니다(§ 문제 5 와 함께 판단).

### 문제 4 — 15분 세션의 완주 보상이 0 이 된다 (작음)

현행 `sessionCompletionReward(15)` 는 xp 20 / 잎사귀 10 을 줍니다. 새 규칙은 25분 미만에
완주 보너스가 없어 15분 이용자의 체감 보상이 내려갑니다. 15분은 "일단 시작하기" 진입로라
여기를 0 으로 만들면 신규 이탈이 늘 수 있습니다.

- **대안** — 15분 완주 +15 (문제 2 의 길이 비례안에 포함됩니다).

### 문제 5 — 기존 대비 획득량이 약 1.9배라 물가가 헐거워졌다 (큼)

기존 하루 1세션(25분·회복 3회) 잎사귀 획득 내역:

| 항목 | 기존 잎사귀 |
|---|---|
| 세션 완주 `sessionCompletionReward(25).points` | 30 |
| 회복 3회 × `REWARD.recovery.points` 5 | 15 |
| 연속 출석 목돈 (30일 합계 330 ÷ 30일) | 약 11 |
| 목표 완료 `REWARD.goalCompleted.points` (설정한 날만) | 0 ~ 10 |
| **합계** | **56 ~ 66** |

| | 기존(잎사귀) | 신규(코인) |
|---|---|---|
| 하루 1세션 획득 | 56 ~ 66 | 125 |
| 옷 1벌 가격 | 240 | 150~250 (대표 200) |
| **옷 1벌까지** | **3.7 ~ 4.3일** | **1.6일** |

가격대는 거의 그대로인데 획득이 **약 2배**로 늘어 옷이 절반 이하 시간에 팔립니다.
초반엔 신나지만 2주 안에 살 게 떨어집니다. 아이템 제작 속도가 소비 속도를 못 따라갑니다.

- **대안 a** — 옷 250~400, 모자·안경 180~300 으로 가격대를 기존 물가에 맞춤.
- **대안 b** — 가격은 두고 분당 1코인(문제 3 대안)으로 획득을 낮춤.
- 권장: **b**. 문제 3 과 한 번에 해결되고 가격표를 다시 흔들지 않습니다.

### 문제 6 — 레어 알 2000 이 시즌(14일)보다 오래 걸린다 (중간)

가벼운 이용자는 단일 저축으로도 16일, 순차 구매로는 24일입니다. 캠퍼스 시즌은 14일
(`SEASON_LENGTH_MS`) 이라 **시즌 안에 레어를 손에 넣을 수 없는 이용자가 다수**입니다.
시즌 한정(1500)도 12일이라, 사려면 시즌 내내 다른 걸 아무것도 못 삽니다.

- **대안 a** — 시즌 한정을 **1000** 으로. 가벼운 이용자 8일 → 시즌 안에 여유가 생깁니다.
- **대안 b** — 상점 시즌을 캠퍼스 시즌(14일)과 분리해 **4주**로 운영.
  실제로 상점 한정은 중간·기말 기준 연 4회(SHOP_SPEC §6)라 14일 주기와 이미 안 맞습니다.
- 권장: **b** (a 와 병행 가능).

### 문제 7 — "하루 첫 세션 +20" 과 "연속 출석 +10" 이 사실상 같은 트리거 (작음)

매일 하는 이용자에게는 둘이 항상 함께 들어옵니다. 다른 건 **연속이 끊겼을 때 10 차이**뿐이라,
화면에 두 줄로 보여줄 만큼의 정보량이 없습니다.

- **대안** — "오늘의 첫 세션 +20 (연속 3일 이상이면 +30)" 한 줄로 합치기.
  수치 합은 그대로고 UI 만 단순해집니다.

## 6. 기존 잎사귀 · XP 를 코인으로 전환하는 방안

### 6.1 잔액 이관

| 기존 | 신규 | 배율 |
|---|---|---|
| 잎사귀 포인트 (`progressionStore.points`) | 코인 | **1 : 1** |
| XP (`progressionStore.xp`) | XP (그대로) | 1 : 1 |
| 인벤토리 · 장착 | 그대로 유지 | – |

배율 1 을 쓰는 이유: 기존 옷값(240)과 새 옷값(150~250)이 겹쳐서, 환산 없이도 구매력이
그대로 이어집니다. 잔액이 늘거나 줄지 않으므로 "왜 내 포인트가 깎였냐"는 문의가 없습니다.
(상수: `LEAF_TO_COIN_RATE = 1`)

### 6.2 성장 단계 임계값은 그대로 둡니다

`CHARACTER_STAGES` 의 250 / 600 / 1000 / 1500 / 2200 을 **바꾸지 않아도 됩니다.**

| | 하루 1세션 XP | 최종 단계(2200)까지 |
|---|---|---|
| 기존 | 약 135 | 약 16.3일 |
| 신규 | 125 | 약 17.6일 |

차이 8% 이내라 성장 속도가 사실상 같습니다. `game.ts` 를 열지 않아도 되는 이유입니다.

### 6.3 이관 순서

1. `coin.ts` 확정 (이 PR)
2. `progressionStore` 에 `coins` 필드 추가 — 최초 로드 시 `coins = points`, `points` 는 읽기 전용으로 남김
3. `features/game/rewards.ts` 의 `applyReward` 가 코인도 함께 적립 (단일 진입점 유지)
4. 상점 가격을 `COIN_PRICES` 기준으로 교체 (`storeItems.ts` → SHOP_SPEC 의 새 구조)
5. 한 시즌 병행 운영 후 `points` 제거

### 6.4 함께 제거할 것

- `REWARD.stretch` (`game.ts`) — 스트레칭 보상
- `CONTRIBUTION_POINTS.stretch_completed` (`features/campus/contribution.ts`)
- `RewardType` 의 `'stretch_completed'` (`features/game/rewards.ts`)
- `RoomEventType` 의 `'stretch_completed'` 는 **남깁니다** — 친구에게 보이는 알림일 뿐
  보상이 아니고, 서버 스키마와 짝이 맞아야 합니다.

### 6.5 `STREAK_MILESTONES` 는 어떻게 되나

기존 3/5/7/14/30일 목돈(20~150P)은 새 규칙의 "연속 출석 하루 +10" 과 성격이 겹칩니다.

- 30일 기준 기존 목돈 합계 = 330 / 신규 일일 합계 = 300 → 총액은 비슷합니다.
- 목돈은 "7일째에 50 받는" 이벤트감이, 일일 +10 은 매일 조금씩의 습관 강화가 강점입니다.
- 권장: **일일 +10 으로 통일하고, 배지(7일·30일)만 남깁니다.** 코인 목돈을 없애도
  `badges` 로 성취감은 유지되고, 획득 경로가 하나로 줄어 어뷰징 표면도 줄어듭니다.
- 이건 **결정 필요 항목**입니다 (§8).

## 7. 어뷰징 시나리오와 차단

| # | 시나리오 | 차단 방법 | 이미 있는 장치 |
|---|---|---|---|
| A1 | 카메라 앞에 사진·인형을 두고 방치 — 분당 2코인만 챙김 | 분 카운트를 **감지 가능한 시간**으로만. `away` · `unstable` 동안 적립 정지 | `REWARD_PAUSED_STATES` (posture.ts) |
| A2 | 일부러 자세를 무너뜨렸다 되돌리기를 반복 (회복 파밍) | 세션당 5회 상한 + 회복 간 20초 쿨다운 | `MAX_REWARDED_RECOVERIES`, `RECOVERY_COOLDOWN_MS` |
| A3 | 25분 세션을 하루 6회 쪼개서 완주 보너스만 수집 | 하루 상한 300 + 완주 보너스 **하루 3회** 제한 + 세션 간 최소 5분 간격 | 하루 상한(신규) |
