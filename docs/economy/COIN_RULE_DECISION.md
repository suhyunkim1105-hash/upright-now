# 코인 규칙 — 확정본

세 벌로 갈려 있던 규칙을 하나로 정합니다. 이 문서가 기준이고, 코드가 여기서
갈라지면 코드가 틀린 것입니다.

## 확정 규칙

| 항목 | 지급 | 조건 |
|---|---:|---|
| **세션 완주** | | 세션 종료 시 한 번, 아래 구간 중 하나 |
| ├ 5분 미만 | 0 | |
| ├ 5–14분 | 10 | |
| ├ 15–29분 | 30 | |
| ├ 30–49분 | 40 | |
| └ 50분 이상 | 60 | 120분을 넘겨도 60 |
| **자세 회복** | +5 | 한 번마다 · 세션당 5회까지 |
| **첫 회복** | +10 | 평생 한 번 |
| **회고 확인** | +3 | 세션당 한 번 · 하루 3회까지 |
| **미니게임 완료** | +10 | 게임별 하루 한 번 |
| **연속 출석** | 3일 10 / 7일 25 / 14일 50 / 30일 100 / 60일 180 | 마일스톤 도달 시 한 번 |
| **하루 획득 상한** | **300** | 모든 원천 합산 |

없는 것: 캠퍼스 체류 코인 · 공간별 차등 · 자세 점수 코인 · 스트레칭 보상.

## 시간을 무엇으로 재는가 ← 이 규칙의 핵심

완주 구간의 분모는 **의자에 앉아 있던 시간이 아니라, 자세 판정이 실제로
돌아간 시간**입니다.

```
seated_minutes = LIVE.goodMs + LIVE.warnMs + LIVE.badMs   (분으로)
chair_minutes  = sit() ~ stand()                          (회고 화면에만)
```

카메라 앞에 사람이 없으면 판정이 안 돌고, 안 돌면 1분도 안 쌓입니다.
자리를 비우면 저절로 멈추므로 따로 감시할 장치가 필요 없습니다.

**이것은 자세 점수화가 아닙니다.** good·warn·bad 를 똑같이 1분으로 셉니다.
자세가 나빠도 시간은 그대로 쌓입니다 — 목이 긴 사람이 유리해지지 않습니다.
재는 것은 "사람이 있었나" 하나뿐입니다 (AGENTS.md §2.2 유지).

## 왜 이렇게 정했나

### 누적형을 버린 이유

민철 판본은 누적형이었습니다 — 캠퍼스에 있으면 10분마다 1, 앉아 있으면
10분마다 2~3. 즉각 피드백이 좋지만 **켜 두기만 해도 쌓입니다.** 멘토가
지적한 어뷰징이 정확히 이것이고, 캠퍼스 체류 코인은 걸어다니기만 해도
주므로 특히 그렇습니다.

### 완주형만으로는 부족한 이유

연우 판본(완주형)도 그냥은 못 막습니다. 앉혀 두고 자리를 비워도 시간은
흐르니까요. 그래서 위의 "분모를 판정 시간으로" 가 같이 가야 합니다.
둘 중 하나만으로는 어느 쪽도 완결되지 않습니다.

### 공간별 차등을 버린 이유

민철 판본은 본관 3 / 도서관 2 로 달랐습니다. 그러면 "어디 앉을지" 가
코인 최적화 문제가 됩니다. 공간을 다르게 느끼게 하는 일은 소리·NPC·
분위기가 맡습니다 (멘토 피드백 ④). 코인으로 하면 취향이 아니라 계산이
됩니다.

### 민철 판본에서 가져온 둘

- **첫 회복 +10** — 처음 성공한 순간을 크게 칭찬하는 장치. 온보딩에서
  "이게 되는구나" 를 만드는 자리라 값이 커야 합니다.
- **회고 확인 +3** — 회고는 이 서비스가 사용자에게 보여 주고 싶은 화면인데,
  안 열면 아무 일도 일어나지 않습니다. 열 이유를 만듭니다.

### 계획 시간 80% 규칙을 뺀 이유

월드는 세션 길이를 미리 정하지 않습니다 (세션 모델, 인수인계 §3-3).
계획이 없는데 계획의 80% 를 따질 수 없습니다.

## 어디서 지급하는가

**서버만 지급합니다.** 로컬은 표시만 합니다. 브라우저 저장값을 고쳐도
잔액이 안 바뀝니다.

| 무엇 | 어디서 |
|---|---|
| 완주 · 회복 · 첫 회복 · 출석 | `world_finish_session()` |
| 회고 확인 | `world_claim_retro(session_id)` |
| 미니게임 | `world_earn_minigame(game)` |
| 하루 상한 300 | `world__grant()` 한 곳에서만 |

지급 경로가 셋이라 각자 세면 상한이 어긋납니다. 그래서 전부 `world__grant`
한 문으로 들어옵니다. `world_coins` 에는 쓰기 정책이 없어서, REST 로 잔액을
직접 PATCH 하면 403 입니다.

## 병합할 때 할 일

1. 민철 판본의 `award(kind, ...)` 에서 `stay`(캠퍼스 체류)와 `seat`(앉기 누적)
   갈래를 지웁니다. `recov`·`retro`·`attend` 는 서버 호출로 바꿉니다.
2. `earn()`(미니게임)은 `world_earn_minigame` 로 보냅니다. 값 5 → **10**.
3. 세션 종료에서 보내는 값을 `SESSION.seatedMs` → **판정 시간**으로 바꿉니다.
   회고 화면에 보여 줄 앉은 시간은 `chair_minutes` 로 따로 보냅니다.
4. 코인 안내 패널(설정)의 표를 위 표로 교체합니다.

## 쓰는 쪽 — 2026-08-18 추가

버는 쪽만 서버가 정하고 **쓰는 쪽이 로컬**이면 장부가 반쪽입니다. 브라우저
콘솔에서 `ROOM.owned.push('egg-swan')` 한 줄이면 800코인짜리를 공짜로
가졌습니다. 그래서 상점도 서버로 옮겼습니다.

| 무엇 | 어디 |
|---|---|
| 값 | `world_shop_items` 표. 클라이언트는 **item_id 만** 보냅니다 |
| 차감 · 보유 등록 | `world_buy_item()` 한 트랜잭션 |
| 입은 것 · 옷 색 · 놓은 가구 | `world_set_loadout()` · `world_set_decor()` |

**하루 상한 300 은 버는 쪽에만 겁니다.** 쓴 액수를 오늘 번 것에서 빼면
상한이 늘어납니다. 그래서 `world_buy_item` 은 `world__grant` 를 안 거칩니다.

오프라인 구매는 **거절합니다**(큐에 안 넣습니다). 세션 종료는 이미 일어난
사실이라 나중에 보내도 뜻이 같지만, 사기는 결과를 모르는 부탁입니다 —
큐에 넣으면 화면이 먼저 "샀다" 고 하고 몇 시간 뒤 서버가 "잔액 부족" 이라고
답할 수 있습니다.

### ponytail — 아직 어긋나 있는 것

프로토타입 `index.html` 의 `award('once:…')` 셋(첫 방문 +5 · NPC 첫 만남 +5 ·
첫 방 꾸미기 +10)은 **위 표에 없는 축**입니다. 서버는 이 코인을 안 주는데
로컬 잔액에는 더해집니다. 그래서 화면 잔액이 서버보다 클 수 있습니다.

서버에 넣을지 없앨지는 이 문서를 고치는 일이라 코드에서 정하지 않았습니다.
대신 상점을 열 때 서버 잔액을 다시 받아 화면을 맞춥니다(`refreshShopCoins`) —
"살 수 있어 보이는데 서버가 거절" 이 되지 않게 하는 것이 먼저입니다.
