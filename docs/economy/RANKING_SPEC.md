# 학교 랭킹 설계

개인 활동 → 학교 점수 → 랭킹으로 이어지는 흐름과, 학교 규모 보정 공식입니다.

이미 있는 코드: [`src/features/campus/contribution.ts`](../../src/features/campus/contribution.ts)
(기여도·상한·정규화), [`schoolChange.ts`](../../src/features/campus/schoolChange.ts)
(학교 변경 제한), [`season.ts`](../../src/features/campus/season.ts) (시즌).

> `src/features/campus/` 는 연우 담당 폴더라 **이 PR 에서는 코드를 고치지 않았습니다.**
> 아래 §3 의 공식 교체는 상의 후 별도 PR 로 진행합니다. (CLAUDE.md 담당 영역)

## 1. 개인 → 학교 → 랭킹

```
세션 이벤트                평가                집계               랭킹
──────────              ────────            ────────           ────────
세션 완주      ┐                     ┐                  ┐
자세 회복 성공  ├→ evaluateContribution ├→ 학교별 합계      ├→ adjustedScore
친구 세션 완주  ┘   (중복·상한·쿨다운)  ┘   (총합 · 참여자 수)┘   내림차순 정렬
```

### 1.1 기여 이벤트와 점수

| 이벤트 | 점수 | 인정 조건 |
|---|---|---|
| 세션 정상 완료 | 100 | 세션당 1회. 중도 종료·데모·QA 는 0 |
| 자세 회복 성공 | 20 | 세션당 5회, 회복 간 20초 이상 |
| 친구 세션 완주 | 50 | 세션당 1회 |
| ~~스트레칭 완주~~ | ~~20~~ | **제거** — 기능을 접기로 했습니다 |

`CONTRIBUTION_POINTS.stretch_completed` 와 `CampusContributionKind` 의
`'stretch_completed'` 를 함께 삭제합니다. (COIN_ECONOMY §6.4)

**자세 점수·등급은 어떤 경로로도 들어가지 않습니다.** 기여 이벤트는 전부
"일어난 행동"이지 "얼마나 잘 앉았나"가 아닙니다. (AGENTS.md §2.2)

### 1.2 개인 점수는 랭킹에 노출하지 않습니다

개인 순위표를 만들면 (1) 개인 활동량이 공개되고 (2) "자세 점수 금지" 규칙을
우회하는 대리 지표가 됩니다. 개인에게는 **자기 기여도만** 보여줍니다
(`CampusSnapshot.myContribution` — 이미 그렇게 돼 있습니다).

## 2. 지금 공식의 문제

현재 `normalizedScore(total, N) = total / √N` 입니다.

학교의 인당 평균 기여를 `c`, 참여자 수를 `N` 이라 하면 `total = N·c` 이므로

```
total / √N  =  N·c / √N  =  c · √N
```

**참여자 수의 제곱근에 그대로 비례합니다.** 인당 기여가 똑같아도 참여자 800명 학교는
40명 학교보다 √(800/40) = **4.47배** 높은 점수를 받습니다. 규모 보정이라는 이름과 달리
규모가 여전히 승부를 가릅니다. 작은 학교는 참여할 이유가 없어집니다.

## 3. 새 보정 공식

인당 평균으로 규모를 완전히 중립화하되, 참여자가 적은 학교의 값이 튀지 않도록
**전체 평균 쪽으로 끌어당깁니다** (shrinkage / 베이즈 가중평균).

```
adjustedScore = (schoolTotal + C × M) / (schoolContributors + C)

  schoolTotal        학교의 시즌 누적 기여도
  schoolContributors 시즌 활동 참여자 수 N
  M                  전체 학교 인당 평균 기여도 = Σtotal / ΣN
  C                  신뢰 상수 = 30
```

`C` 는 "가상의 평균적인 참여자 30명을 모든 학교에 얹는다"는 뜻입니다.

- N 이 크면 `C` 의 영향이 사라져 → **인당 평균**에 수렴 (규모 중립)
- N 이 작으면 전체 평균 `M` 쪽으로 끌려가 → 소수 인원의 극단값이 눌림

### 순위표 등재 조건

```
qualified = schoolContributors >= 20     (MIN_RANKED_CONTRIBUTORS)
```

shrinkage 만으로는 "3명이 몰아서 파밍" 을 못 막습니다(§5 참고). 참여자 수 하한이
실질 방어선이고, 미달 학교는 순위 대신 **"집계 중 (참여자 14/20)"** 으로 표시합니다.
목표가 보이면 오히려 친구를 부르는 동기가 됩니다.

### 시즌 인당 인정 상한

```
SEASON_CAP_PER_MEMBER = 4200     (= 일일 상한 600 × 7일분)
```

한 사람이 학교 총점에 넣을 수 있는 상한입니다. 14일 시즌을 매일 최대로 채우면
8,400 이 되는데, 그 절반에서 끊어 **소수의 초과 활동가가 학교 순위를 혼자 결정하지
못하게** 합니다. 개인이 받는 코인·XP 는 이 상한과 무관합니다(학교 집계에만 적용).

## 4. 시뮬레이션 — 가상 학교 5개

| 학교 | 규모 | 참여자 N | 인당 기여 | 총 기여 |
|---|---|---|---|---|
| A | 대형 | 800 | 300 | 240,000 |
| B | 대형 | 600 | 250 | 150,000 |
| C | 중형 | 150 | 420 | 63,000 |
| D | 소형 | 40 | 500 | 20,000 |
| E | 초소형 | 6 | 700 | 4,200 |

전체 평균 `M = 477,200 / 1,596 = 299.0`, `C = 30`.

### 지금 공식 (`total / √N`)

| 순위 | 학교 | 계산 | 점수 |
|---|---|---|---|
| 1 | **A** (대형) | 240,000 / 28.28 | 8,485 |
| 2 | B (대형) | 150,000 / 24.49 | 6,124 |
| 3 | C (중형) | 63,000 / 12.25 | 5,144 |
| 4 | D (소형) | 20,000 / 6.32 | 3,162 |
| 5 | E (초소형) | 4,200 / 2.45 | 1,715 |

**인당 기여가 가장 낮은 A(300)가 1위, 가장 높은 E(700)가 꼴찌.** 규모 순서 그대로입니다.

### 새 공식 (`(total + 30M) / (N + 30)`)

| 순위 | 학교 | 계산 | 점수 | 비고 |
|---|---|---|---|---|
| 1 | **D** (소형) | (20,000 + 8,970) / 70 | **413.9** | 인당 500 |
| 2 | C (중형) | (63,000 + 8,970) / 180 | 399.8 | 인당 420 |
| 3 | A (대형) | (240,000 + 8,970) / 830 | 300.0 | 인당 300 |
| 4 | B (대형) | (150,000 + 8,970) / 630 | 252.3 | 인당 250 |
| – | E (초소형) | (4,200 + 8,970) / 36 | 365.8 | **N=6 < 20 → 집계 중** |

읽는 법:

- **A 는 인당 기여(300)와 점수(300.0)가 거의 같습니다.** N 이 커서 보정이 사라졌고,
  규모 이점도 사라졌습니다. 이게 "규모 중립"의 의미입니다.
- **D(40명)가 1위** — 40명이 열심히 하면 800명 학교를 이깁니다. 작은 학교의 참여 동기가 생깁니다.
- **E 는 인당 700 으로 가장 열심이지만 점수는 365.8 로 눌립니다.** 6명 표본은 신뢰할 수
  없기 때문이고, 어차피 N 하한에 걸려 순위표에 오르지 않습니다.
- 순위가 지금 공식과 **정확히 뒤집혔습니다**(A>B>C>D → D>C>A>B). 도입 시 기존 상위 학교의
  반발이 예상되므로 **시즌 경계에서 바꾸고**, 두 점수를 한 시즌 병행 표시하기를 권합니다.

### C 값을 바꾸면

| C | A(800) | C(150) | D(40) | E(6) | 성격 |
|---|---|---|---|---|---|
| 0 | 300.0 | 420.0 | 500.0 | 700.0 | 순수 인당 평균. 소수 정예가 항상 이김 |
| 10 | 300.0 | 412.4 | 460.2 | 486.9 | 보정 약함 |
| **30** | **300.0** | **399.8** | **413.9** | **365.8** | **권장** |
| 100 | 299.9 | 371.6 | 356.4 | 321.7 | 보정 강함. 대형이 다시 유리해짐 |

C=30 은 "40명 규모까지는 어느 정도 눌리고, 150명부터는 실력이 그대로 드러나는" 지점입니다.

## 5. 규모 보정으로 막지 못하는 것 — 솔직한 한계

3명이 시즌 내내 일일 상한(600)을 채우면 총 25,200, `adjustedScore = 1,035` 로
**압도적 1위**가 됩니다. shrinkage 로는 못 막습니다. 인당 기여가 실제로 8,400 이니까요.

실제 방어선은 셋입니다.

1. **참여자 하한 20명** — 3명 학교는 아예 순위에 못 오릅니다.
2. **계정 확보 비용** — 20명을 채우려면 학교 인증 20건이 필요합니다
   (`features/campus/verification.ts`). 1인 1학교 + 변경 쿨다운 7일이 재사용을 막습니다.
3. **세션 자체의 어뷰징 차단** — 일일 상한 600 을 채우려면 25분 세션 3회를
   **감지 가능한 상태로** 해야 합니다. 20계정 × 3세션 = 하루 25시간의 실제 카메라 시간입니다.
   이 방어가 뚫리는 유일한 경로는 "카메라 앞 사진 방치"이고,
   그건 COIN_ECONOMY §7 A1 에서 막습니다.

즉 **랭킹 어뷰징의 진짜 방어선은 랭킹 공식이 아니라 자세 판정 연동**입니다.

## 6. 랭킹 항목

| 부문 | 지표 | 보정 |
|---|---|---|
| 종합 | 총 기여도 | `adjustedScore` |
| 세션 최다 참여 | 완료 세션 수 | 같은 공식, `total` 자리에 세션 수 |
| 다시 앉기 | 자세 회복 성공 횟수 | 같은 공식 |
| 꾸준함 | 참여자 평균 연속 출석일 | 이미 인당 값이라 보정 불필요, N≥20 만 적용 |
| 완주율 | 완료 세션 / 시작 세션 | 이미 비율이라 보정 불필요 |

### ⚠️ "자세 유지 우수 학교" 는 넣을 수 없습니다

요청 항목에 있었지만 두 가지 문제가 있습니다.

1. **규칙 위반** — "자세 유지 우수"는 자세의 좋고 나쁨을 학교 단위로 등급화한 것입니다.
   AGENTS.md §2.2 · CLAUDE.md 2번(자세 점수·등급·정상/비정상 표시 금지)에 정면으로 걸립니다.
2. **지표 자체가 역설** — 대체 후보인 "회복 성공 횟수"가 많다는 건 **자세를 자주 무너뜨렸다**는
   뜻이기도 합니다. "회복 많음 = 자세 우수" 로 읽히면 사실과 반대인 표시가 됩니다.

그래서 **"다시 앉기"** 라는 행동 이름으로 바꿨습니다. 회복 성공은 CLAUDE.md 가 명시적으로
허용한 지표이고, 이름이 행동을 그대로 가리키면 우열 해석이 붙지 않습니다.
문구는 "회복 성공이 가장 많았던 학교" 로 씁니다. **결정 필요 항목입니다(§9 R1).**

## 7. 시즌 초기화와 명예의 전당

### 초기화

- 시즌 종료 시 기여도·참여자 수·타일 소유를 **전부 0 으로** 되돌립니다.
- 초기화 직전 스냅샷을 `CampusArchivedSeason` 으로 보존합니다(이미 있는 타입).
- 개인의 코인·XP·인벤토리는 **초기화하지 않습니다.** 시즌은 학교 경쟁의 단위지
  개인 성장의 단위가 아닙니다. (AGENTS.md §2.5)

### 명예의 전당

```ts
export interface HallOfFameEntry {
  seasonId: string
  seasonName: string
  /** 'overall' | 'sessions' | 'recovery' | 'streak' | 'completion' */
  category: string
  schoolId: string
  schoolName: string
  /** 표시용 색 — 공식 색이 아닙니다 (constants/campus.ts) */
  color: string
  score: number
  contributors: number
  archivedAt: number
}
```

- 시즌마다 **부문별 1위 5개 행**만 남깁니다. 2위 이하는 보존하지 않습니다.
- 개인 식별 정보는 한 글자도 들어가지 않습니다. 학교 이름·색·점수·참여자 수뿐입니다.
- 화면은 시즌 역순 목록. 각 시즌 카드에 종합 1위를 크게, 나머지 부문은 한 줄씩.
- "비공식 프로토타입" 고지(`CAMPUS_COPY.unofficialGame`)를 명예의 전당 상단에도 답니다.
  과거 기록일수록 "공식 순위"로 오해되기 쉽습니다.

## 8. 어뷰징 차단 요약

| 시나리오 | 차단 | 상태 |
|---|---|---|
| 한 사람이 하루 종일 파밍 | 일일 상한 600 | ✅ `CONTRIBUTION_LIMITS.dailyCap` |
| 한 사람이 시즌 내내 파밍 | 시즌 인당 인정 상한 4,200 | 🆕 신규 |
| 회복 반복 파밍 | 세션당 5회 + 20초 쿨다운 | ✅ `CONTRIBUTION_LIMITS` |
| 같은 이벤트 재전송 | eventId · sessionId 중복 차단 | ✅ `evaluateContribution` |
| 짧은 시간 대량 이벤트 | 분당 12건 제한 | ✅ `eventsPerMinute` |
| 카메라 앞 방치 | 감지 가능 시간에만 기여 인정 | ⚠️ 세션 쪽 연동 필요 |
| 여러 학교에 중복 기여 | 1인 1학교 (memberId 기준) | ✅ `campus/identity.ts` |
| 이기는 학교로 갈아타기 | 시즌 1회 + 7일 쿨다운, 기여도 미이전 | ✅ `schoolChange.ts` |
| 소수 계정으로 학교 순위 조작 | 참여자 하한 20명 | 🆕 신규 |
| 유령 학교 만들기 | 학교 인증 필요 | ✅ `verification.ts` |

신규로 필요한 건 **시즌 인당 상한**과 **참여자 하한** 둘뿐입니다.

## 9. 결정이 필요한 항목

| # | 항목 | 기본값 | 이유 |
|---|---|---|---|
| R1 | "자세 유지 우수 학교" 부문 | **"다시 앉기"(회복 성공 최다)** 로 대체 | §6 — 규칙 위반 + 지표 역설 |
| R2 | 보정 공식 교체 시점 | 시즌 경계, 한 시즌 병행 표시 | 순위가 통째로 뒤집힙니다 |
| R3 | 신뢰 상수 `C` | 30 | §4 표 참고. 커뮤니티 규모를 보고 조정 |
| R4 | 참여자 하한 | 20명 | 초기 이용자 수가 적으면 순위표가 텅 빕니다 |
| R5 | 시즌 인당 인정 상한 | 4,200 | 상한을 낮출수록 "다수 참여"가, 높일수록 "열정"이 유리 |
| R6 | 캠퍼스 시즌 길이 | 14일 유지 | 상점 시즌(4주)과 다릅니다. 통일할지 결정 필요 |
