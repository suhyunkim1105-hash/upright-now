# 최초 진입 동의 흐름 설계 (초안)

> ⚠️ **법률 자문을 받기 전의 설계 초안입니다.**
> 동의 항목의 필수/선택 구분은 법적 판단이 필요합니다.
> 구현 전에 [PRIVACY_POLICY.md](PRIVACY_POLICY.md) · [TERMS_OF_SERVICE.md](TERMS_OF_SERVICE.md)
> 와 함께 검토를 받아 주세요.

작성일 2026-08-12

## 1. 설계 원칙

1. **한 번에 다 묻지 않습니다.** 기능을 쓰는 순간에 그 기능의 동의만 받습니다.
   처음부터 카메라·학교 이메일·AI 를 전부 묻는 화면은 이탈률만 올립니다.
2. **필수와 선택을 눈으로 구분합니다.** 선택 항목을 거부해도 서비스의 핵심
   (혼자 하는 자세 세션)은 그대로 동작해야 합니다. 이는 「개인정보 보호법」
   제22조 제5항의 요구이기도 합니다.
3. **전체 동의 체크박스를 기본 선택 상태로 두지 않습니다.** 모두 해제된 상태로 시작합니다.
4. **거부할 때 무슨 일이 생기는지 미리 알려 줍니다.**
5. **동의를 받는 화면과 권한을 요청하는 순간을 붙여 둡니다.**
   브라우저 권한창이 뜨기 직전 화면에서 설명을 끝내야 합니다.

## 2. 전체 흐름 지도

현재 라우트(`src/constants/routes.ts`)에 **새 화면 하나(`/welcome`)** 를 추가하고,
나머지는 기존 화면 안에서 처리하는 안입니다.

```
처음 방문
   │
   ├─ [신규] /welcome ──── 서비스 소개 + 필수 동의 (약관·개인정보·연령)
   │                        └ 동의 안 하면 진행 불가 (여기서만 막습니다)
   │
   ├─ /onboarding/name ─── 닉네임 (개인정보 아님을 안내)
   │
   ├─ /profiles ────────── 학습 환경 선택
   │
   ├─ /camera ──────────── 📷 카메라 설명 + "카메라 연결하기" 버튼
   │                        └ 이 버튼을 눌러야 브라우저 권한창이 열립니다
   │
   ├─ /calibration ─────── 5초 개인 기준 등록
   │
   └─ /session/setup ───── 세션 시작

나중에, 그 기능을 쓸 때만
   ├─ 친구 방 만들기·입장 ── 닉네임·과목·목표가 친구에게 보인다는 안내
   ├─ 캠퍼스 학교 인증 ───── 학교 이메일 수집 동의 (선택)
   └─ 결과 화면 AI 회고 ──── 외부 AI 전송 동의 (선택, 매번)  ← 이미 구현돼 있음
```

### 3.2 동작 규칙

| 규칙 | 내용 |
|---|---|
| 기본 상태 | 모든 체크박스 **해제** |
| 전체 동의 | 누르면 3개가 모두 켜지고, 하나라도 해제하면 전체 동의도 해제 |
| 버튼 활성화 | 필수 3개가 모두 켜져야 `동의하고 시작하기` 가 눌립니다 |
| `[보기 >]` | 전문을 화면 안에서 열어 봅니다. 새 탭으로 내보내 흐름을 끊지 않습니다 |
| 데모 | 동의 없이도 데모는 볼 수 있게 합니다. **데모는 카메라를 켜지 않고 아무것도 저장하지 않습니다** |
| 뒤로가기 | 동의 전에 다른 경로로 들어와도 이 화면으로 되돌립니다 |

### 3.3 저장하는 동의 기록

```
upright-now:consent
{
  termsVersion:    "0.1",   // 동의한 약관 버전
  privacyVersion:  "0.1",   // 동의한 방침 버전
  ageConfirmed:    true,    // 만 14세 이상 확인
  agreedAt:        1786... // 동의 시각 (ms)
}
```

- 저장된 버전이 현재 버전보다 낮으면 **변경 내용을 요약해 보여 주고 다시 동의**를 받습니다.
- 이 기록은 기기 안에만 남고 서버로 보내지 않습니다.

### 3.4 만 14세 미만 처리

`(필수) 만 14세 이상이에요` 를 켜지 않으면 시작할 수 없습니다.
서비스가 대학생을 대상으로 하고 생년월일을 수집하지 않으므로,
**자기 확인 체크박스**를 기본안으로 둡니다.

> `검토 필요` — 자기 확인만으로 충분한지, 생년(연도만) 입력이나 법정대리인
> 동의 절차가 필요한지는 법률 검토가 필요합니다. 서비스가 실제로 만 14세 미만을
> 수집하지 않는 구조라는 점(§2.5 수집하지 않는 정보)이 판단에 반영돼야 합니다.

## 4. 카메라 권한 요청 직전 — `/camera`

**이 화면은 이미 구현돼 있습니다** (`src/app/routes/CameraIntro.tsx`).
아래는 지금 있는 것과 보완할 것입니다.

### 4.0 ⚠️ 먼저 막아야 할 구멍 — `/calibration` 직접 진입

`/camera` 는 안내를 잘 하고 있지만, **`/calibration` 에는 진입 가드가 없습니다.**

`src/app/routes/Calibration.tsx` 는 화면이 뜨자마자 `useEffect` 에서 `start()` 를
부르고, 그 안에서 `getUserMedia` 가 실행됩니다
(`src/app/router/AppRoutes.tsx` 에 `/calibration` 가드 없음).

그래서 주소창에 `https://upright-now.vercel.app/calibration` 을 직접 치거나
북마크로 들어오면 **아무 설명 없이 브라우저 권한창이 바로 뜹니다.**
`/camera` 에 적어 둔 "영상은 저장하지 않아요" 를 한 번도 못 본 채로요.

**고치는 법** — `/calibration` 진입 시 아래를 확인하고, 하나라도 아니면
`/camera` 로 보냅니다.

| 확인 | 아니면 |
|---|---|
| `/welcome` 필수 동의를 마쳤는가 | `/welcome` 으로 |
| `/camera` 안내를 거쳐 왔는가 | `/camera` 로 |

가장 간단한 방법은 `/camera` 의 CTA 가 라우터 state 로 표시를 남기고,
`/calibration` 이 그 표시가 없으면 `<Navigate to="/camera" replace />` 하는 것입니다.

### 4.1 이미 잘 되어 있는 것

| | |
|---|---|
| ✅ | `/camera` 를 거쳐 오는 정상 경로에서는 이용자가 `카메라 연결하기` 를 누른 뒤에만 권한창이 뜹니다 (위 §4.0 의 직접 진입은 예외) |
| ✅ | "권한은 아래 버튼을 누를 때만 요청해요" 라고 미리 알립니다 |
| ✅ | "영상은 저장하지도, 외부로 보내지도 않아요" 를 3단계 안내에 넣었습니다 |
| ✅ | "카메라 없이 3분 데모" 라는 거부 경로가 항상 있습니다 |
| ✅ | 의료 판정이 아니라는 문구를 함께 보여 줍니다 |

### 4.2 권한창이 뜨기 전에 반드시 보여야 할 것 (체크리스트)

브라우저 권한창은 "이 사이트에서 카메라를 사용하려고 합니다" 한 줄만 보여 줍니다.
**왜 필요한지, 무엇을 하는지, 어떻게 끄는지는 우리 화면이 책임져야 합니다.**

| # | 항목 | 현재 | 보완안 |
|---|---|---|---|
| 1 | 왜 필요한가 | ✅ | 그대로 |
| 2 | 무엇을 하는가 (기준 등록 → 차이 감지) | ✅ | 그대로 |
| 3 | **어디로 가는가 — 아무 데도 안 감** | ✅ | 그대로 |
| 4 | 얼마나 오래 켜져 있는가 | ⚠️ 없음 | **"세션이 끝나면 카메라가 자동으로 꺼져요" 한 줄 추가** |
| 5 | 어떻게 끄는가 | ⚠️ 없음 | **"언제든 브라우저 주소창에서 권한을 끌 수 있어요" 한 줄 추가** |
| 6 | 거부하면 어떻게 되는가 | ✅ (데모 버튼) | **"카메라 없이도 데모로 흐름을 볼 수 있어요" 를 문장으로도 표기** |
| 7 | 녹화가 아님 | ⚠️ 암시만 | **"녹화하지 않아요. 화면에 보이는 영상은 이 브라우저 안에만 있어요"** |

### 4.3 추가 권장 문구

`카메라 연결하기` 버튼 **바로 아래**에 작은 글씨로:

```
버튼을 누르면 브라우저가 카메라 권한을 물어봐요.
영상은 녹화되지 않고, 세션이 끝나면 카메라가 자동으로 꺼져요.
언제든 주소창의 권한 아이콘에서 다시 끌 수 있어요.
```

### 4.4 권한이 거부됐을 때

이미 오류 문구가 있습니다 (`Calibration.tsx`).
**다시 켜는 방법**을 한 줄 더 붙이는 것을 권합니다.

```
카메라 권한이 필요해요.
주소창 왼쪽의 🔒 아이콘 → 카메라 → '허용' 으로 바꾼 뒤 다시 시도해 주세요.
지금은 카메라 없이 데모로 흐름을 확인할 수 있어요.
```

## 5. 친구 방에 들어갈 때

동의 화면을 따로 띄우지 않습니다. **방 만들기·입장 화면 안의 안내**로 충분합니다.

`ROOM_PRIVACY` 문구가 이미 있습니다.

> 친구에게는 닉네임, 진행 상태, 게임 이벤트만 보여요.
> 카메라와 개인 자세 상태는 공유하지 않아요.

### 보완이 필요한 곳 — 과목·목표 입력란

방을 만들 때 입력한 **과목·목표는 서버에 저장되고 같은 방의 친구에게 보입니다**
(`rooms.subject`, `rooms.goal`). 입력란 바로 아래에 다음을 넣어 주세요.

```
같은 방 친구들에게 보여요. 개인적인 내용은 적지 말아 주세요.
```

## 7. AI 회고 (선택) — 이미 구현돼 있음

결과 화면의 `AiReportCard` 가 **매번** 동의를 받습니다
(`src/features/ai-report/AiReportCard.tsx`). 설계 원칙에 맞는 좋은 구조입니다.

| | |
|---|---|
| ✅ | 기본값이 체크 해제 |
| ✅ | 체크하지 않으면 버튼이 비활성 |
| ✅ | "동의하지 않으면 아무 정보도 전송하지 않아요" 명시 |
| ✅ | 한 번 동의를 기억해 두지 않고 매번 다시 물음 |

### 보완 권장 — 무엇이 나가는지 펼쳐 보기

지금은 "세션 요약" 이라고만 적혀 있습니다.
`무엇이 전송되나요? >` 를 눌러 8개 항목을 그대로 볼 수 있게 하면
동의의 구체성이 확보됩니다.

```
계획 시간 · 진행 시간 · 감지 가능 시간 · 자리 비움 시간 ·
회복 기회 수 · 회복 성공 수 · 최고 연속 회복 · 완주 여부

닉네임, 과목, 목표, 카메라 영상, 자세 좌표는 보내지 않아요.
```

| 닉네임 수정 | ✅ 있음 | **여기에도 `checkNickname` 을 걸어야 합니다** (온보딩만 막으면 우회됩니다) |
| 전체 데이터 초기화 | ✅ 있음 | 서버 데이터(익명 계정·학교 인증)도 지울지 결정 — [PRIVACY_POLICY.md](PRIVACY_POLICY.md) §4.1 |
