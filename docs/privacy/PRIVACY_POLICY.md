## 0. 가장 먼저 알아야 할 것

### 📷 카메라 영상은 이 기기 밖으로 나가지 않습니다.

- 웹캠 화면은 **브라우저 안에서만** 분석되고, 분석이 끝난 프레임은 **즉시 버려집니다.**
- 영상·사진·스냅샷·얼굴 이미지·자세 좌표는 **어떤 서버에도 저장되거나 전송되지 않습니다.**
- 저장·전송하는 것은 "몇 번 회복했는가" 같은 **숫자 요약**뿐입니다.
- 이 원칙은 코드에 다음과 같이 강제돼 있습니다.
  - 프레임 분석 (`src/features/posture-engine/usePoseDetection.ts`) — 매 프레임을 분석 직후 폐기
  - 친구 방 전송 (`src/features/rooms/roomEvents.ts`) — 허용 필드 밖의 값이 섞이면 전송 자체를 차단
  - AI 회고 전송 (`src/features/ai-report/contract.ts`) — 8개 숫자 외에는 스키마가 거부

## 1. 서비스 소개와 이 방침의 적용 범위

UpRight Now 는 오래 앉아 공부하는 대학생을 위한 **자세 회복 습관 웹앱**입니다.
웹캠으로 이용자가 직접 등록한 기준 자세와 지금 자세의 **차이**를 감지하고,
자세를 회복하면 픽셀 캠퍼스에서 캐릭터가 성장하고 학교 영토전에 기여합니다.

이 방침은 웹사이트 `https://upright-now.vercel.app` 및 관련 API 에 적용됩니다.

> **UpRight Now 는 의료기기가 아니며 의료 서비스를 제공하지 않습니다.**
> 진단·치료·통증 위험도를 판정하지 않고, 자세 점수나 정상/비정상 등급도 만들지 않습니다.
> 자세한 내용은 [이용약관](TERMS_OF_SERVICE.md) 제9조를 봐 주세요.

## 2. 수집하는 정보

### 2.1 기기 안에만 남는 정보 (브라우저 localStorage)

서버로 가지 않습니다. 브라우저를 지우면 함께 사라집니다.
저장 키는 모두 `upright-now:` 로 시작합니다.

| 저장 키 | 담기는 값 | 왜 필요한가 |
|---|---|---|
| `upright-now:user` | 닉네임, 온보딩 완료 여부, 학습 프로필(도서관·내 공간·팀플·내 모드), 기준 등록 여부, 소리 설정, PiP 자동 열기, 내가 만든 응원 문구(최대 3개) | 개인화·화면 표시 |
| `upright-now:calibration` | **개인 기준 자세의 요약 수치**(각도·비율 등 파생값), 활성 기준 id, 민감도 | 지금 자세와 비교 |
| `upright-now:progression` | XP, 잎사귀 포인트, 출석 날짜, 완료 세션 수, 보유·장착 아이템, 배지, 연속 보상 기록 | 캐릭터 성장·상점 (XP·포인트는 §2.2(5) 대로 서버에도 쌓입니다) |
| `upright-now:sessions` | 세션 요약 기록 — 시작·종료 시각, 계획/실제 시간, 감지 가능 시간, 자리 비움 시간, 회복 횟수, 최고 콤보, 획득 XP·포인트, **이용자가 직접 입력한 과목·목표·다음 할 일**, AI 회고 결과 | 기록 화면·결과 화면 |
| `upright-now:campus` | 선택한 학교, 직접 고른 테마 색, 학교 변경 이력 | 캠퍼스 테마 |
| `upright-now:campus-ledger` | 기여 원장(중복·일일 상한 판정용) | 중복 적립 방지 |
| `upright-now:campus-outbox` | 아직 서버에 반영되지 않은 기여 이벤트 큐 | 네트워크 끊김 시 유실 방지 |
| `upright-now:campus-mock` | 서버 없이 동작할 때의 임시 영토 데이터 | 개발·오프라인 |
| `upright-now:campus-member` | 이 브라우저에서만 쓰는 임의 문자열 식별자 | 중복 기여 차단 |

**개인 기준 자세 수치는 좌표 원본이 아니라 파생 수치입니다.**
얼굴·신체를 복원할 수 있는 형태가 아니고, 서버로 보내지 않습니다.

### 2.2 서버(Supabase)에 저장되는 정보

서버 저장은 **친구 방에 들어가거나 캠퍼스 화면을 연 뒤부터** 시작됩니다.
그 전까지는 익명 계정 자체가 만들어지지 않으므로 **서버에 아무것도 저장되지 않습니다.**

한 번 익명 계정이 만들어지면, 그 뒤로는 혼자 하는 세션의 XP·포인트도
서버에 함께 쌓입니다(§2.2 (5)).

#### (1) 계정 — 회원가입을 요구하지 않습니다

| 항목 | 설명 |
|---|---|
| 익명 사용자 ID (UUID) | Supabase 익명 로그인으로 자동 발급. 이메일·전화번호·비밀번호를 받지 않습니다 |

#### (2) 친구 방 (최대 10인)

| 테이블 | 저장 항목 |
|---|---|
| `rooms` | 방 코드(6자리), 방장 사용자 ID, **이용자가 입력한 과목·목표 문구**, 세션 길이, 방 상태, 공동 보스 HP·방어막, 생성·시작·종료 시각 |
| `room_members` | 방 ID, 사용자 ID, **닉네임**, 역할(방장/멤버), 참가 상태(`ready`·`focusing`·`resting`·`away`·`completed`), 캐릭터 단계, 참가 시각, 마지막 응답 시각 |
| `room_events_processed` | 이벤트 ID, 방 ID, 사용자 ID, 이벤트 종류, 발생 시각 (중복 보상 차단용) |

> ⚠️ **방을 만들 때 입력한 과목·목표는 서버에 저장됩니다.**
> 같은 방에 있는 친구에게 보입니다. 개인적인 내용은 적지 말아 주세요.

#### (3) 실시간 이벤트 (Supabase Realtime Broadcast — DB 저장 없음)

방 안에서 순간적으로 오가고 저장되지 않습니다.

| 필드 | 값 |
|---|---|
| `type` | `recovery_earned` · `stretch_completed` · `session_completed` · `reaction_sent` |
| `participantId` | 참가자 ID |
| `nickname` | 닉네임 (최대 12자) |
| `reaction` | 정해진 10종 반응 중 하나 |
| `reactionText` | 직접 쓴 응원 문구 (최대 16자, HTML·제어문자 제거 후) |
| `timestamp` | 시각 |

**허용 목록 밖의 필드가 섞이면 전송·수신 양쪽에서 차단합니다.**
자세 좌표, `bad` 상태, 나쁜 자세 지속 시간은 친구에게 절대 공개되지 않습니다.

#### (4) 캠퍼스 영토전

| 테이블 | 저장 항목 |
|---|---|
| `campus_memberships` | 사용자 ID, 선택한 학교, 시즌, 선택·변경 시각, 시즌 내 변경 횟수 |
| `campus_verifications` | 사용자 ID, **인증된 학교 ID**, **이메일 도메인**(예: `snu.ac.kr`), 인증 시각 |
| `campus_district_contributions` | 이벤트 ID, 시즌, 자치구, 학교 ID, **회원 해시값**, 세션 ID, 기여 종류, 점수, 시각 |
| `campus_district_territories` / `_events` | 자치구별 점령 학교·점수·변동 기록 (개인 정보 없음) |

**기여 기록에는 이메일·닉네임이 들어가지 않습니다.** 사용자 ID를 서버에서 해시한 값만 씁니다.

#### (5) 성장 기록 (XP·포인트)

익명 사용자 계정이 만들어진 뒤에는 XP·포인트도 서버에 함께 쌓입니다.
서버가 보상량을 계산해 중복 지급과 조작을 막기 위해서입니다.

| 테이블 | 저장 항목 |
|---|---|
| `progression_balances` | 사용자 ID, 누적 XP, 누적 포인트, 생성·수정 시각 |
| `progression_reward_events` | 사용자 ID, 이벤트 ID, 이벤트 종류(`recovery_success`·`session_completed`·`stretch_completed`·`goal_completed`·`friend_session_bonus`·`streak_bonus`), **세션 ID**, 지급된 XP·포인트, 계획 시간(분), 부가 정보(연속 출석 일수·배지), 발생 시각 |

- **XP·포인트 숫자는 앱이 보내지 않습니다.** 앱은 "무슨 일이 있었는지"(이벤트 종류)만
  보내고 지급량은 서버 규칙이 정합니다.
- 과목·목표 문구, 자세 상태, 자세 좌표는 여기에 포함되지 않습니다.
- 서버 동기화에 실패해도 앱은 그대로 동작합니다(기기 안 기록이 기준).

#### (6) 학교 이메일 인증

캠퍼스 영토전에 참여할 때만 씁니다. 인증하지 않아도 지도와 순위는 볼 수 있습니다.

| 어디에 | 무엇이 |
|---|---|
| Supabase Auth (`auth.users`) | **이메일 주소 원본**, 인증 확인 시각 |
| 앱 테이블 (`campus_verifications`) | 학교 ID, 이메일 **도메인만**, 인증 시각 |

> **이메일 주소 원본은 앱 테이블로 복사되지 않습니다.**
> 다른 이용자는 여러분의 이메일을 볼 수 없습니다.
> 현재 인증 가능한 도메인은 10개 대학(`snu.ac.kr`, `yonsei.ac.kr`, `korea.ac.kr`,
> `sogang.ac.kr`, `skku.edu`, `hanyang.ac.kr`, `cau.ac.kr`, `khu.ac.kr`,
> `hufs.ac.kr`, `uos.ac.kr`)입니다.

### 2.3 AI 회고를 만들 때 외부(Google Gemini)로 나가는 정보

**결과 화면에서 동의 체크박스를 켜고 `AI 회고 만들기` 를 누를 때만** 전송됩니다.
누르지 않으면 아무것도 나가지 않습니다.

전송되는 값은 **정확히 아래 8개 숫자·상태뿐**입니다.

| 항목 | 값 |
|---|---|
| `plannedMinutes` | 계획한 분 |
| `elapsedMinutes` | 실제 진행 분 |
| `detectableMinutes` | 자세를 감지할 수 있었던 분 |
| `awayMinutes` | 자리 비움 분 |
| `recoveryOpportunities` | 회복 기회 수 |
| `recoveries` | 회복 성공 수 |
| `bestCombo` | 최고 연속 회복 |
| `status` | `completed` 또는 `aborted` |

**보내지 않는 것:** 세션 ID, 닉네임, 과목·목표 문구, 카메라 영상·사진·프레임,
자세 좌표·랜드마크, 자세 상태, 나쁜 자세 지속 시간, 학교, 이메일, 건강 정보.

- Gemini 호출은 `store: false` 로 보내 **Google 쪽에 대화가 보관되지 않도록** 요청합니다.
- API 키는 서버에만 있고 브라우저 번들에 들어가지 않습니다.
- 같은 IP 기준 10분에 3회로 제한합니다.
- **AI 회고는 기본값이 꺼짐입니다.** 운영 환경 설정이 모두 켜져 있을 때만 화면에 나타납니다.

### 2.4 자동으로 남는 접속 기록

| 항목 | 어디에 | 설명 |
|---|---|---|
| IP 주소, 접속 시각, User-Agent | Vercel (호스팅), Supabase (API) | 서비스 제공에 따라 자동 생성되는 서버 로그. 별도 분석 도구(Google Analytics 등)를 **쓰지 않습니다** |
| IP 주소, User-Agent | jsDelivr CDN, Google (`storage.googleapis.com`) | 자세 감지 모델 파일을 내려받을 때 발생. **영상·자세 데이터는 함께 가지 않습니다** |

`검토 필요` — Vercel·Supabase 서버 로그의 실제 보관 기간은 각 사업자의 정책을 확인해 명시해야 합니다.

### 2.5 수집하지 않는 정보

- 실명, 주민등록번호, 전화번호, 주소, 결제·카드 정보
- 카메라 영상·사진·스냅샷·얼굴 이미지
- 프레임별 랜드마크·자세 좌표 원본
- 통증·질환·복용 약 등 건강 정보
- 위치 정보(GPS), 주소록, 다른 앱 사용 기록
- 광고 식별자, 크로스 사이트 추적 쿠키

## 3. 이용 목적

| 정보 | 목적 |
|---|---|
| 개인 기준 자세 수치 | 지금 자세와의 **차이**를 감지 (의료 판정 아님) |
| 세션 요약 | 결과·기록 화면 표시, 캐릭터 성장·출석 계산 |
| 닉네임 | 친구 방·결과 화면에서의 표시 |
| 익명 사용자 ID | 방 접근 권한 확인, 중복 보상 차단 |
| 방 정보·참가 상태 | 함께 집중하는 방 기능 |
| 서버 성장 기록 (XP·포인트·보상 이벤트) | 보상량을 서버가 계산해 중복 지급·조작을 막기 위해 |
| 학교 인증 정보 | 캠퍼스 영토전 참여 자격 확인 (같은 학교 사칭 방지) |
| 기여 기록 | 학교별 영토 점수 집계, 중복·상한 판정 |
| 세션 집계 8개 값 | 이용자가 직접 요청한 AI 회고 문장 생성 |

**하지 않는 것:** 광고, 프로파일링, 제3자 판매, 자동화된 의사결정.

## 4. 보관 기간과 파기

### 4.1 기기 안의 정보

| 언제 사라지나 | 방법 |
|---|---|
| 이용자가 지울 때 | 설정 → **전체 데이터 초기화** (닉네임·기준·기록·XP·포인트·아이템 전부 삭제) |
| 이용자가 브라우저 데이터를 지울 때 | 브라우저 설정에서 사이트 데이터 삭제 |

별도의 보관 기간을 두지 않습니다. 이용자가 지울 때까지 이 기기에 남습니다.

> ⚠️ `검토 필요` — **현재 "전체 데이터 초기화" 는 Supabase 로그인 세션을 지우지 않습니다.**
> 초기화 후에도 같은 익명 사용자 ID 로 이어집니다. 이 동작을 그대로 둘지,
> 로그아웃까지 포함할지 결정하고 이 방침에 반영해야 합니다.
> (`src/lib/storage/local.ts` `clearLocal` 은 `upright-now:` 로 시작하는 키만 삭제)

### 4.2 서버의 정보

| 대상 | 지금의 실제 동작 |
|---|---|
| `room_members` (참가자 행) | 마지막 응답으로부터 **45초**가 지나면 자동 삭제 |
| 일반 친구 방 | 참가자 전원이 45초 이상 무응답이면 `closed` 로 표시 (**행은 남음**) |
| 상시 친구 방 | **7일** 동안 아무 변화가 없으면 `closed` 로 표시 (**행은 남음**) |
| Supabase Auth 이메일 | 계정 삭제 시 함께 삭제 |
| 학교 인증 (`campus_verifications`) | 계정 삭제 시 함께 삭제 (`on delete cascade`) |
| 성장 기록 (`progression_balances`, `progression_reward_events`) | 계정 삭제 시 함께 삭제 (`on delete cascade`) |
| 방 (`rooms`, `room_events_processed`) | 방장 계정 삭제 시 함께 삭제. 그 밖에는 **기간 제한 없이 보관** |
| 학교 소속 (`campus_memberships`) | **자동 삭제 규칙 없음** (계정과 연결된 외래키가 없어 계정을 지워도 남습니다) |
| 캠퍼스 기여 (`campus_district_contributions`) | **자동 삭제 규칙 없음.** 시즌은 삭제되지 않고 `archived` 로 바뀌므로 기록이 계속 쌓입니다 |

> ⚠️ `검토 필요` — **서버 데이터의 보관 기간이 아직 정해져 있지 않습니다.**
> 위 표는 "지금 코드가 이렇게 동작한다"는 사실이고, 개인정보처리방침이
> 요구하는 "보유 기간"이 아닙니다. 공개 전에 아래를 정해야 합니다.
>
> 1. 종료된 방(`rooms`)을 언제 지울지 — 지금은 `closed` 표시만 되고
>    방 코드·과목·목표 문구가 남습니다 (예: 종료 후 30일)
> 2. 지난 시즌의 캠퍼스 기여 기록을 언제 지울지 (예: 시즌 종료 후 1년)
> 3. `campus_memberships` 에 `references auth.users(id) on delete cascade` 를
>    붙일지 — 지금은 계정을 지워도 학교 소속이 남습니다
> 4. 오래 쓰지 않은 익명 계정을 언제 정리할지
>
> 캠퍼스 기여 기록에는 이메일·닉네임이 없고 사용자 ID를 시즌별로 해시한
> 값(`md5(사용자ID:시즌)`)만 들어 있어 개인 식별성은 낮습니다.

파기 방법: 데이터베이스에서 행을 삭제(`DELETE`)합니다. 별도 백업본을 만들지 않습니다.

## 10. 안전성 확보 조치

- **온디바이스 처리** — 카메라 영상은 브라우저를 떠나지 않습니다.
- **전송 필드 화이트리스트** — 허용 목록 밖의 값이 섞이면 전송 자체를 막습니다.
- **RLS(행 수준 보안)** — 방 멤버만 그 방의 데이터를 읽을 수 있고, 본인 인증 기록만 조회됩니다.
- **점수·HP 서버 계산** — 클라이언트가 보낸 점수를 그대로 믿지 않습니다.
- **API 키 분리** — Gemini 키는 서버 환경 변수에만 두고 브라우저 번들에 넣지 않습니다.
- **HTTPS** — 모든 통신을 암호화합니다.
- **입력 정리** — 닉네임·응원 문구는 길이 제한, HTML·제어문자 제거를 거칩니다.
- **오류 로그에 자세 데이터 금지** — 로그에 좌표·상태를 남기지 않습니다.
