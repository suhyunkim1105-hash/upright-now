# 캐릭터 성장·경험치 밸런스 명세

## 1. 성장 구조

성장은 `누적 XP → 레벨 → 캐릭터 단계`로 계산한다. `stage`를 별도 저장하지 않고
XP에서 파생해 데이터 불일치를 막는다.

| 레벨 | 누적 XP | 캐릭터 표현 |
| ---: | ---: | --- |
| 1 | 0 | 뽀각 거북 |
| 2 | 250 | 꿈틀 거북 |
| 3 | 600 | 빼꼼 거부기린 |
| 4 | 1,000 | 반듯 거부기린 |
| 5 | 1,500 | 쭉쭉 기린 |
| 6 | 2,200 | 우뚝 기린 (현재 만렙) |

현재 코드의 `CHARACTER_STAGES`와 일치하는 6단계 기준이다. 향후 15레벨로 확장할 때는
이 표를 DB 설정 테이블로 옮기고, 기존 누적 XP는 보존한다.

## 2. XP를 얻는 곳

모든 보상은 서버 `progression_reward_rules`와 `progression_reward_events`를 통해 지급한다.
클라이언트는 보상량을 보내지 않는다.

| 이벤트 | XP | 제한 | 판정 기준 |
| --- | ---: | --- | --- |
| 15~29분 세션 완주 | 60 | 세션당 1회 | 정상 완료 |
| 30~49분 세션 완주 | 80 | 세션당 1회 | 정상 완료 |
| 50분 이상 세션 완주 | 120 | 세션당 1회 | 정상 완료 |
| 자세 회복 | 25 | 세션당 최대 2회, 하루 100 XP | 회복 성공 이벤트 |
| 스트레칭 완주 | 10 | 세션당 1회 | 동작 완료 |
| 오늘 목표 완료 | 15 | 세션당 1회 | 완료 화면에서 확정 |
| 친구 세션 보너스 | 20 | 세션당 1회 | 양쪽 세션 완료 |
| 출석 마일스톤 | 20~150 | 마일스톤별 1회 | 3/5/7/14/30일 |

캠퍼스 기여도는 XP와 별도다. 캠퍼스 기여도는 개인 XP에 직접 합산하지 않고
학교·시즌 점수로만 반영한다.

### 학교별 참여 인원 보정

학교 순위에는 이미 참여 인원 보정 점수가 적용된다.

```text
보정 점수 = 총 기여도 / sqrt(max(활성 참여자 수, 1))
```

- `총 기여도`: 해당 시즌 학교의 모든 기여 원장 합계
- `활성 참여자 수`: 해당 시즌에 한 번 이상 기여한 고유 사용자 수
- `보정 점수`: 순위 표시용 점수
- 영토 점령 계산: 기존 raw 기여도·방어/공격 점수를 사용

따라서 참여 인원이 많은 학교가 유리한 것은 완화되지만, 참여자가 많다는 이유로
학교 점수가 자동으로 커지지는 않는다. 동점이면 총 기여도, 그 다음 학교 ID 순으로
정렬한다. 실제 운영 데이터가 쌓인 뒤 `sqrt`의 강도를 조정할 수 있도록 후속 단계에서
시즌별 보정 계수를 설정값으로 분리한다.

## 3. 마이너스가 되는 상황

장기 성장 원칙상 이미 얻은 XP를 차감하지 않는다. 캐릭터가 이전 단계로 퇴화하면
사용자가 누적 성취를 잃게 되고, 현재 제품 계약에도 맞지 않기 때문이다.

대신 아래 상황은 해당 세션의 보상을 줄이거나 지급하지 않는다.

| 상황 | 처리 |
| --- | --- |
| 세션 중도 종료 | 완주 XP 0, 이미 받은 회복 XP는 유지 |
| 감지 가능 시간 80% 미만 | 완주 XP 0 |
| 1분 빠른 점검 | XP 0, 캠퍼스 기여도 0 |
| 장시간 `bad` 상태 | 회복 보상 추가 지급 중지 |
| 같은 이벤트 재전송 | XP 0, `duplicate` 반환 |
| 하루 회복 XP 한도 초과 | 초과분 0, 원장에는 거절 사유 기록 |
| 비인증 캠퍼스 기여 | XP·캠퍼스 점수 모두 0 |

즉, “마이너스”는 누적 XP를 깎는 방식이 아니라 기대 보상을 잃는 방식이다. 향후
실제 감점이 필요하면 XP가 아니라 시즌성 캠퍼스 기여도나 당일 보너스에만 적용한다.

## 4. 만렙까지 걸리는 시간

만렙 기준은 2,200 XP다. 자세 회복·스트레칭·목표 보너스는 개인차가 크므로
세션 완주 XP만으로 기본 시간을 계산한다.

| 플레이 방식 | 1회 XP | 필요한 완주 수 | 1일 2회 기준 |
| --- | ---: | ---: | ---: |
| 15~29분 세션 | 60 | 37회 | 약 19일 |
| 30~49분 세션 | 80 | 28회 | 약 14일 |
| 50분 이상 세션 | 120 | 19회 | 약 10일 |

회복·스트레칭·목표 보너스까지 정상적으로 얻는 사용자는 대략 **2~4주**에 만렙에
도달한다. 하루 사용량이 적은 사용자는 4~6주를 목표 범위로 본다.

이 값은 초기 밸런스다. 실제 데이터가 쌓이면 `평균 일일 XP`, `7일 유지율`,
`레벨별 이탈률`을 기준으로 XP 표를 조정한다. 이미 지급된 원장 데이터는 수정하지 않고
새 이벤트부터 새 규칙을 적용한다.

## 5. 구현 순서

1. `progression_level_rules`에 레벨 임계값을 저장한다.
2. `progression_reward_rules`에 이벤트별 XP·제한을 저장한다.
3. 서버 RPC에서 멱등성, 세션 완료, 하루 한도를 검사한다.
4. 로컬 `applyReward`를 서버 RPC와 연결한다.
5. 성장 화면에 현재 XP·다음 레벨·최근 보상·예상 남은 XP를 표시한다.
6. 관리자/QA 화면에서 XP 규칙을 시뮬레이션한다.
