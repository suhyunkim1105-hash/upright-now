# 캠퍼스 타일 전투 연출 설계

## 목표

인증된 학생의 캠퍼스 기여가 발생했을 때, 해당 타일 위에서 작은 기린(공격)과 거북이(방어)가 2~3초 동안 전투 애니메이션을 재생한다. 지도 크기와 레이아웃은 유지하며, 전투가 끝나면 서버의 권위 있는 타일 상태를 표시한다.

## 범위

- 기존 `campus_territory_events`와 Supabase Realtime 구독을 전투 이벤트의 원천으로 사용한다.
- 공격 캐릭터는 기린, 방어 캐릭터는 거북이로 고정한다.
- 학교별 테마 색상은 캐릭터 테두리·공격 효과·방어 효과에 적용한다.
- 새 데이터베이스 테이블이나 캐릭터 위치 저장은 추가하지 않는다.
- 인증된 학교만 기여 RPC를 호출할 수 있으며, 비인증 사용자는 지도와 전투 결과를 볼 수만 있다.

## 사용자 흐름

1. 인증된 사용자가 지도에서 타일을 선택하고 정상적인 기여를 완료한다.
2. 서버의 원자적 기여 RPC가 점수와 타일 상태를 갱신하고 영토 이벤트를 기록한다.
3. Realtime 구독 중인 각 클라이언트가 이벤트를 수신한다.
4. 이벤트의 공격 학교·방어 학교·타일 좌표를 기준으로 작은 기린과 거북이를 타일 위에 표시한다.
5. 2~3초 동안 전투 효과를 재생한다.
6. 전투 종료 시 캐릭터와 효과를 제거하고 서버 상태를 화면에 반영한다.

## 데이터 계약

기존 영토 이벤트의 `id`, `territory_id`, `kind`, `from_school_id`, `to_school_id`, `created_at`을 사용한다.

- `to_school_id`: 공격 또는 새 점령 학교
- `from_school_id`: 기존 점령 학교(없으면 중립)
- `kind`: `contested`, `captured`, `reinforced` 등 기존 이벤트 종류
- 이벤트 `id`: 클라이언트별 중복 애니메이션을 막는 멱등 키

공격 학교는 `to_school_id`, 방어 학교는 `from_school_id`를 우선 사용한다. 방어 학교가 없으면 거북이는 중립 방어 색상으로 표시한다.

## UI/애니메이션

- 지도 컨테이너의 크기와 타일 배치는 변경하지 않는다.
- 전투 타일 안쪽에 오버레이 레이어를 두고 작은 캐릭터 두 개를 표시한다.
- 기린: 짧은 이동/공격 흔들림과 공격 효과.
- 거북이: 방패 또는 흔들림 효과와 방어 효과.
- 캐릭터는 타일 밖으로 넘치지 않도록 크기와 `overflow`를 제한한다.
- `prefers-reduced-motion` 사용자는 움직임을 최소화하고 짧은 페이드만 표시한다.
- 동시에 여러 타일에서 이벤트가 오면 타일별로 독립적으로 재생하며, 같은 이벤트 ID는 한 번만 재생한다.

## 상태 및 예외 처리

- Realtime이 `SUBSCRIBED`가 아니면 새 전투 애니메이션을 시작하지 않는다.
- 재연결 후 전체 스냅샷이 갱신되며 과거 이벤트를 다시 애니메이션하지 않는다.
- 서버 상태 갱신이 애니메이션 종료보다 늦으면 캐릭터 제거 후 다음 스냅샷을 권위값으로 적용한다.
- 이벤트가 누락되거나 중복되어도 지도 상태와 점수는 서버 RPC 결과를 기준으로 한다.
- 인증되지 않은 사용자의 기여 시도는 기존 `verification_required` 경로로 거부한다.

## 테스트 기준

- 두 개의 브라우저에서 서로 다른 인증 학교로 같은 타일에 기여했을 때 두 화면에 같은 전투가 표시된다.
- 전투 중 지도 크기와 주변 타일 위치가 변하지 않는다.
- 전투 종료 후 두 화면의 타일 소유 학교·점수·로그가 일치한다.
- 동일 이벤트가 중복 수신되어도 캐릭터가 한 번만 나타난다.
- Realtime 연결을 끊었다가 복구해도 지도는 최신 서버 상태로 복원되고 과거 전투가 재생되지 않는다.
- 모션 감소 설정에서 과도한 이동 없이 결과가 표시된다.

## 구현 경계

이번 작업은 기존 캠퍼스 지도와 Realtime 이벤트를 활용한 클라이언트 전투 연출에 한정한다. 실제 캐릭터 이동 경로, 전투력 수치, 별도 PvP 매칭, 음향 효과, 새 SQL 마이그레이션은 후속 작업으로 분리한다.
