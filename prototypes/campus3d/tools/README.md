# 랜딩 점토 캐릭터를 3D 월드로 옮기는 길

랜딩의 `char-*-3d.webp` 넷은 우리가 힉스필드로 뽑아 둔 **기준 그림**입니다.
월드의 `assets/chars/*.glb` 는 그 그림에서 나온 3D 판인데, **거북이만
망가져 있었습니다** — 등껍질이 배에 붙고 등이 비어 있었습니다.

원인은 생성기가 아니라 **소스 그림**이었습니다. 넷을 나란히 놓으면 보입니다.

| | 소스 자세 | 3D 결과 |
|---|---|---|
| 기린 | 서서 정면, 소품 없음 | 좋음 |
| 개구리 | 서서 정면, 소품 없음 | 좋음 |
| 펭귄 | 서서 정면, 소품 없음 | 거의 좋음(뒤통수 이음새) |
| **거북이** | **앉아서 3/4 각도, 책을 듦** | **망가짐** |

생성기는 **안 보이는 면을 지어냅니다.** 등이 안 보이는 그림을 주면 등껍질을
앞으로 끌어옵니다. 힉스필드 문서에도 그대로 적혀 있습니다 —
*"메시는 소스 이미지에 있는 것만 재현한다. 소품·자세를 바꾸려면 이미지를
먼저 고쳐라."*

---

## 순서

### 1. 3면도 한 장 만들기 (1크레딧)

`char-<종>-cut.webp` 를 레퍼런스로 넣고 **앞·옆·뒤를 한 장에** 그립니다.
세 장을 따로 뽑으면 서로 다른 캐릭터가 나옵니다 — 한 그림 안에 있어야
같은 캐릭터입니다. `turtle-turnaround.png` 가 그렇게 나온 판입니다.

프롬프트에서 못 빼면 안 되는 것

- 레퍼런스와 **같은 캐릭터·같은 점토 재질·같은 색**이라고 못박기
- **서 있고**, 소품을 **들지 않고**, 팔을 몸에서 살짝 뗀 A 자세
- 뒤 그림에는 **얼굴이 없다**고 명시 (안 그러면 뒤통수에 눈을 그립니다)
- 배경은 흰 단색, 그림자 없음, 셋이 같은 높이·같은 바닥선

### 2. 셋으로 자르기 (0크레딧)

```bash
node -e "…sharp…extract…"   # 1344×768 을 448 씩 셋으로
```

### 3. Tripo 멀티뷰 (9크레딧)

`tripo_h3_1_multiview_to_3d`, 앞·옆·뒤 순서로.
`texture_alignment: original_image`, `orientation: align_image`.

**`texture_quality` 와 `geometry_quality` 를 `detailed` 로 올리면 9 → 18
입니다.** 표준으로 충분합니다.

**`face_limit` 을 걸어 두세요.** 안 걸면 714,279 정점 · 38MB 가 나옵니다.
(나머지 셋은 4~6천 정점 · 330~440KB 입니다.)

### 4. 줄이기 — `decimate.mjs` (0크레딧)

```bash
VCOL=1 node --max-old-space-size=4096 decimate.mjs raw.glb small.glb 8000
```

**색을 정점에 굽습니다.** 이 생성기의 UV 아틀라스는 조각이 잘아서, 얼마를
남기고 줄이든 이음새가 찢어집니다(3만 정점에서도 그랬습니다). 텍스처를 버리고
색을 정점에 넣으면 UV 가 없어지므로 찢어질 곳도 없습니다. 매끈한 점토라
잃는 것이 거의 없습니다.

두 번 당한 것

- **UV 를 뭉치는 키에 넣으면 안 됩니다.** 같은 자리인데 UV 가 다른 정점이
  다른 덩어리가 되면서, 한자리에 덩어리가 여럿 생겨 틈이 벌어집니다.
  색은 **줄이기 전에** 원본 UV 로 떠 두고, 뭉칠 때는 자리만 봅니다
- **V 를 뒤집으면 안 됩니다.** glTF 의 UV 원점은 좌상단입니다. `1-v` 로
  읽었더니 등껍질 색이 머리로, 눈이 배로 올라갔습니다

### 5. 뼈 옮겨 붙이기 — `reskin.mjs` (0크레딧)

```bash
node reskin.mjs small.glb ../assets/chars/turtle.glb out.glb
```

**리깅을 사지 않습니다**(Meshy 리깅 5, 동작까지 8, 동작이 넷이니 32).
기존 GLB 에 이미 뼈와 동작 넷이 들어 있으니 살가죽만 갈아 끼웁니다.
가장 가까운 옛 정점의 가중치를 그대로 가져오는 방식이고, 같은 종에
같은 자세라 잘 듭니다.

### 6. 확인 — `../glbcheck.html`

```
glbcheck.html                      네 종 앞·뒤·전신
glbcheck.html?sp=turtle&turn=1     한 종을 여섯 방향
glbcheck.html?turn=1&anim=walk&t=.45   걷는 자세로 — 뼈가 먹었는지는 움직여야 압니다
```

## 코드가 요구하는 계약

`chars.js` 의 `loadCharacters` 가 이걸 그대로 기대합니다. 어기면 조용히
안 움직이거나 옆구리를 보이며 걷습니다.

```
클립  idle · walk · run · sit      (이 이름 그대로)
뼈    root · spine · head · arm.L · arm.R · leg.L · leg.R
정면  +X                            (코드가 -90° 돌려 세웁니다)
크기  아무거나                       (코드가 키 1.9 로 맞춥니다)
```

`reskin.mjs` 는 옛 파일을 뼈대로 쓰므로 이 계약이 저절로 지켜집니다.

## 다시 안 뽑고 고치는 길 — `bakevcol.mjs`

**펭귄은 이걸로 끝났습니다. 0크레딧입니다.**

뒤통수의 균열은 메시가 깨진 것이 아니라 **UV 섬이 맞닿는 자리에서 색이
새던 것**이었습니다. 그러니 다시 뽑을 필요가 없었습니다 — 이미 있는
GLB 의 텍스처를 정점 색으로 굽고 UV 를 없애면, 샐 경계가 사라집니다.

```bash
node bakevcol.mjs ../assets/chars/penguin.glb out.glb --subdiv
```

`decimate.mjs` 와 다른 점은 **뼈와 동작을 그대로 둔다**는 것입니다.
새로 뽑은 민짜 메시가 아니라, 이미 쓰고 있는 캐릭터를 손볼 때 씁니다.

`--subdiv` 는 삼각형을 한 번 넷으로 쪼갭니다. 안 쪼개면 4,166 정점이라
눈이 각지고 뒤통수 자국이 희미하게 남습니다. 쪼개면 14,356 이 되고
깨끗해집니다. 중점의 뼈는 **섞지 않고 더 무겁게 매달린 쪽**을 씁니다 —
섞으면 팔 정점이 다리 뼈를 물고 늘어집니다.

**먼저 이걸 시도해 보세요.** 메시 모양이 멀쩡하고 얼룩·균열만 문제라면
크레딧을 쓸 일이 아닙니다. 거북이는 등껍질이 배에 붙어 있어서 — 모양이
틀려서 — 다시 뽑아야 했습니다.
