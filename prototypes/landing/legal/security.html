1. 우리가 지키는 원칙

수집하지 않는 것이 가장 안전합니다

Deskfit의 첫 번째 보안 조치는 애초에 갖고 있지 않는 것입니다.

없는 것그래서
비밀번호유출될 비밀번호가 없습니다
이메일·전화번호계정 탈취로 얻을 신원 정보가 없습니다
카메라 영상·좌표서버가 털려도 영상이 나오지 않습니다
결제 정보결제 기능 자체가 없습니다

적용된 조치

영역조치
전송모든 통신 HTTPS
인증익명 인증. 발급된 토큰은 브라우저에만 저장
권한행 수준 보안(RLS)으로 각 행은 본인 익명 ID만 읽기·쓰기
키 관리클라이언트에는 공개용 익명 키만. 관리자 키는 코드·저장소에 두지 않음
지급 검증코인 지급량·하루 상한을 서버가 다시 계산. 클라이언트 값을 신뢰하지 않음
입력 검증닉네임 비속어 필터, 채팅 길이 제한
의존성외부 스크립트는 고정 버전으로 벤더링, CDN 임의 최신 로드를 피함

2. 알려진 한계 (솔직하게)

학생 팀 프로젝트로서 아직 갖추지 못한 것들입니다. 숨기는 것보다 적어 두는 편이

낫다고 판단했습니다.

  • 보안 감사를 받지 않았습니다. 외부 전문 기관의 점검 이력이 없습니다.
  • 버그 바운티 금전 보상이 없습니다. 감사 인사와 (원하시면) 크레딧 표기만

드릴 수 있습니다.

  • 24시간 대응 체계가 없습니다. 아래 응답 목표는 최선의 노력 기준입니다.
  • 침해사고 대응 절차가 문서로만 있고 훈련된 적은 없습니다.

3. 취약점을 발견하셨다면

신고 방법

ikmc554@mju.ac.kr 로 메일 주세요. 제목에 [보안] 을 붙여 주시면

더 빨리 확인합니다.

아래를 함께 주시면 확인이 빨라집니다.

  • 취약점 유형 (예: XSS, 권한 우회, 코인 부정 획득)
  • 재현 절차 — 가능한 한 단계별로
  • 영향 범위 — 무엇을 할 수 있게 되는지
  • 발견 환경 — 브라우저·버전·OS
  • 스크린샷이나 짧은 영상 (있다면)

응답 목표

단계목표 시간
접수 확인 회신3영업일 이내
유효성 판단 결과 회신14일 이내
수정 또는 완화 조치심각도에 따라 협의

공개 시점

수정이 끝난 뒤 공개해 주시기를 부탁드립니다.

아직 고쳐지지 않은 취약점을 먼저 공개하면 이용자가 위험해집니다.

연구 목적의 공개 일정이 있다면 메일로 협의해 주세요.

4. 테스트할 때 지켜 주셨으면 하는 것

연구는 환영하지만, 아래는 삼가 주세요.

하지 말아 주세요

  • 다른 이용자의 데이터에 접근하거나 변경하는 행위
  • 서비스를 마비시키는 부하 테스트(DoS)·대량 자동 요청
  • 다른 이용자를 대상으로 한 소셜 엔지니어링·피싱
  • 물리적 침입, 팀원 개인 계정 공격
  • 취약점을 이용해 얻은 데이터를 보관·배포하는 행위

괜찮습니다

  • 본인 계정·본인 브라우저 범위의 테스트
  • 소스 코드 열람과 정적 분석 (클라이언트 코드는 공개돼 있습니다)
  • 재현에 필요한 최소한의 요청

위 범위를 지켜 선의로 신고해 주신 분께는 법적 조치를 취하지 않습니다.

5. 관심 있는 영역

특히 아래를 봐 주시면 도움이 됩니다.

  1. 코인 부정 획득 — 서버 검증을 우회해 지급 상한을 넘길 수 있는지
  2. RLS 우회 — 다른 사람의 세션 기록이나 코인을 읽을 수 있는지
  3. XSS — 닉네임·채팅 입력으로 스크립트가 실행되는지
  4. 카메라 원칙 위반 — 우리가 모르는 경로로 영상·좌표가 나가는지

(이건 발견되면 최우선으로 고칩니다)

6. 이미 알고 있는 것 (신고하지 않으셔도 됩니다)

  • 클라이언트 코드가 난독화되지 않아 읽을 수 있는 점 — 의도한 것입니다
  • localStorage 값을 브라우저에서 고칠 수 있는 점 — 화면 표시만 바뀌고

서버 지급에는 영향을 주지 않습니다

  • 익명 키(anon key)가 클라이언트에 노출된 점 — 공개 전제로 설계된 키이며,

실제 권한은 RLS가 통제합니다

7. 침해사고가 발생하면

이용자의 정보와 관련된 사고가 확인되면 아래대로 알려 드립니다.

  1. 사고를 인지한 즉시 원인 파악과 확산 차단
  2. 72시간 이내 랜딩 페이지에 공지 — 무엇이, 언제, 어느 범위로
  3. 필요한 경우 관계 기관 신고
  4. 원인과 재발 방지 대책을 사후 공개
