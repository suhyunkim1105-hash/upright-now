01 홈 재구성

카드 세 장이 각자 제목을 달고 있었는데, 셋 다 같은 행동이었습니다.

문제
코드로 참여 / 내 상시방 / 우리 학교 방 — 카드 셋이 세로로 서 있었습니다. 제목이 셋, 눈이 훑을 곳이 셋이었습니다.
원인
셋 다 이미 있는 방에 들어간다는 같은 행동입니다. 다른 건 출처뿐인데, 출처는 카드가 아니라 필터입니다.
조치
목록 하나 + 세그먼트(내 방 / 명지대 / 전체)로 합쳤습니다. 학교가 40곳이 되어도 같은 구조로 버팁니다. 코드로 참여는 방 만들기 상자 우측 하단으로 옮겼습니다 — 만들기와 들어가기는 같은 결정의 양면이라 한자리에 있어야 합니다.

중간에 잡은 것 — 방 만들기 상자의 발판에 position: relative가 걸려 있어, 상자 전체를 덮어야 할 확장 링크가 아래 띠 안에만 갇혀 있었습니다. 제목을 눌러도 아무 일이 없었습니다. 코드만 봐서는 안 보이고, 렌더된 화면을 실제로 눌러 봐야 나오는 종류입니다.

이어서 두 열을 세로로 쌓았습니다. 1400px 화면에서 두 열로 두면 파란 상자가 좁은 칸에 갇히고 목록도 답답했는데, 쌓으니 상자는 필요한 만큼만 쓰고 목록이 남는 높이를 전부 가져갑니다. 목록은 1440에서 3열, 1280에서 2열입니다.

들어가기 → 방 찾기로 바꿨습니다. 만들기와 찾기는 같은 모양의 세 글자라 화면의 두 반쪽이 서로를 이름 짓습니다. 스트릭 띠는 마이페이지로 옮기고, 비운 높이는 방 만들기 상자가 가져갔습니다.

02 흰색 사다리

무채색 회색은 "고르지 않은 색"으로 읽힙니다.

배경·구분선·채움을 전부 강조색의 색상각(220°)을 아주 옅게 머금은 흰색으로 바꿨습니다. 인접 단계 대비를 1.02~1.09로 잡아 면이 나뉜 것은 보이되 선처럼 도드라지지는 않게 했습니다.

#FCFDFF카드
#F6F8FC바탕
#EDF1F8가라앉은 면
#E1E8F2경계에 가까운 면

채움도 회색이 아니라 같은 220°를 머금은 반투명입니다 (rgba(96,116,148,α)). 어느 흰색 위에 올려도 그 흰색의 성격을 유지합니다. 다크 모드는 아직 만들지 않았습니다.

03 결과 화면과 공유 카드

카드를 여러 장 늘어놓으면 무엇을 볼지 매번 고르게 됩니다.

한 화면에 한 가지로 줄였습니다. 가장 큰 것은 앉아 있던 시간 하나이고, 측정·회복·경험치는 그 아래 한 줄로 붙습니다. 공유 카드는 1080×1350 캔버스에 직접 그려, 화면에 보이는 것과 저장되는 그림이 같습니다. 웹폰트가 붙은 뒤에 그려야 캔버스에도 같은 서체가 나오므로 document.fonts.ready를 기다립니다.

규칙 1 — 채움 위 글자색이 흰색에서 먹색으로

파랑은 흰 글자를 얹는 색이었습니다. 라임 위 흰 글자는 1.10, 먹글자는 16.52입니다. 강조색이 어두울 때만 맞았던 color: #fff 11곳을 --on-tint로 바꿨습니다.

규칙 2 — 라임은 면, 올리브는 선

라임은 흰 바탕과 1.03입니다. 면으로는 쓸 수 있지만 2px 선택 링, 4px 진행 막대, 포커스 테두리, 13px 링크로 그리면 흰 화면에서 그냥 없습니다. 그 30여 곳을 올리브 --tint-ink(흰 카드 위 6.89)로 옮겼습니다.

공유 카드방 만들기 상자를 닮게 만든 것이라 같은 규칙으로 뒤집음

가장자리가 필요했습니다. --tint-line은 #7A8C00입니다 — 라임 계열로 흰 바탕과 3:1을 넘기는 가장 밝은 값입니다. 처음 고른 #C9E01F는 1.39라 "테두리처럼 보이지만 테두리가 아닌" 것이었습니다.

특히 15단계 사다리가 문제였습니다. 라임(지난 칸)과 회색(미래 칸)이 1.01 — 밝기가 같고 색상만 다릅니다. 그 색상 구분이 안 되는 사람에게는 진행도가 통째로 사라집니다. 지난 칸에 테두리를 두르고 현재 칸을 먹색 칩으로 찍어 색에 기대지 않게 했습니다.

06 설정 화면 신설 신규

레퍼런스에서 가져온 건 "행의 해부"입니다 — 제목 / 보조 설명 / 오른쪽 컨트롤.

오른쪽에 오는 것조건예
토글되돌리는 비용 0음성 안내, 미니 창
값 + 화살표다음 단계 필요자세 기준, 닉네임
상태(읽기 전용)앱이 못 바꿈카메라 권한

카메라 권한은 컨트롤이 아닙니다. 웹앱이 권한을 되돌릴 수 없어서, 토글로 그리면 껐다 켤 때 안 켜집니다. 그건 화면이 거짓말한 것입니다. 상태만 보여주고 바꾸는 곳을 문장으로 안내합니다.

종속 행도 가져왔습니다. 미니 창에 카메라 보이기는 미니 창이 꺼지면 아예 사라집니다. 형제로 나란히 두면 꺼진 상태에서도 만질 수 있는 죽은 행이 남습니다.

데스크톱 스케일

처음엔 폭만 680px로 묶었더니 모바일 목록을 넓은 화면에 붙여 놓은 꼴이었습니다 — 제목은 왼쪽 끝, 컨트롤은 오른쪽 끝, 가운데 600px이 비고, 행 높이는 손가락 기준. 그룹 이름을 왼쪽 여백으로 빼 두 단으로 나누고, 행 높이를 마우스 기준(70→60px)으로 줄였습니다. 스위치는 전부 같은 세로선에 섭니다.

바꾸는 흐름

행 → 가운데 모달 → 검증 → 완료 → 바뀐 행 옆 토스트

레퍼런스는 바텀시트지만 그건 엄지가 닿는 자리이고 키보드가 밀어 올려주는 자리라 모바일에서 옳은 것입니다. 데스크톱에서는 둘 다 의미가 없습니다. 대신 시트가 주던 "위쪽 맥락이 보인다"가 필요한 읽기는 우측 패널로 갈랐습니다.

토스트에 버튼을 안 달았습니다. 레퍼런스는 화면 맨 위에 확인 버튼 달린 띠를 띄우는데, 모바일 상단이라 놓치기 쉬워서 붙인 것이고 버튼이 붙는 순간 그건 작은 모달입니다. 방금 만진 자리에 뜨면 누를 게 없습니다.

07 마이페이지와 설정의 경계

두 화면이 같은 내용으로 흘러가고 있었습니다.

마이페이지 = 내 데이터와 내 기준  /  설정 = 이 기기에서 앱이 도는 방식

마이페이지설정
요약 띠 (연속 · 오늘 · 이번 주 회복)알림 — 음성 안내
AI 세션 회고 → 우측 패널미니 창 — 사용 + (종속) 카메라 표시
내 정보 — 닉네임 / 학교 / 응원 문구카메라 — 권한 상태
모드별 자세 기준데이터 — 의견 보내기 / 지우기

전에는 닉네임·학교가 양쪽에 다 있었고, 자세 기준이 설정의 "카메라" 아래 있었습니다. 자세 기준은 앱 동작이 아니라 "내 기준"이라 마이페이지 몫입니다.

마이페이지를 여덟 덩이에서 셋으로

375px 레퍼런스에서 블록 여덟 개가 괜찮았던 건 스크롤이 순서를 만들어줬기 때문입니다. 한 번에 두세 개만 보이고 위에서 아래로 읽힙니다. 1440px에서 같은 여덟 개는 동시에 보이고, 스크롤이 주던 순서가 사라져 눈이 들어갈 입구가 없어집니다.

넓은 화면의 대응은 열을 늘리는 게 아니라 첫 화면 덩이를 줄이는 것입니다. 스트릭과 회복은 같은 질문에 답하므로 한 띠로 합쳤습니다 — 위는 숫자, 아래는 문장.

학교는 텍스트 입력이 아닙니다

가입할 때 학교 메일로 인증한 소속이라, 여기서 아무 이름이나 적을 수 있으면 인증이 의미를 잃고 "같은 학교 방"이 성립하지 않습니다. 다시 인증으로만 열어 뒀습니다.

자세 기준을 모드에 매달았습니다

"자세 기준"과 "모드별 기준"을 따로 두면 같은 것을 두 번 묻는 셈입니다. 기준은 언제나 어떤 모드의 기준이고, 따로 두면 "방을 도서관 모드로 열었는데 자세 기준에는 도서관이 없는" 상태가 생깁니다. 방 만들기가 이미 쓰는 MODES에 기준을 매달았습니다.

08 세션 시계와 PiP 중요

시계가 아예 없었습니다.

문제
18:42는 마크업에 박힌 문자열이었고 세는 코드가 없었습니다. 3초 만에 끝내도 25분으로 적혔습니다.
원인
뒤 화면들이 전부 계획 시간을 읽고 있었습니다. 스트레칭 문구, 결과 숫자, 경험치, 공유 카드가 각자 state.focusMin을 베껴 썼습니다.
조치
시작 시각 하나를 찍고, Date.now() 기준으로 틱을 그리고, endSession() 한 곳에서 결과를 굳힙니다. 뒤 화면은 그 기록만 읽습니다. 완주 기준은 마법사에 적어 둔 그대로 계획한 시간의 80%입니다.

세션은 화면을 떠나도 계속 돕니다

앉아 있는 걸 재는 기능인데 마이페이지 한 번 열었다고 시계가 멈추면 그때부터 숫자가 거짓이 됩니다. 끝내는 건 세션 종료 버튼 하나뿐입니다.

이게 PiP이 작동하는 조건이기도 합니다. PiP은 버튼이 아니라 visibilitychange에 겁니다 — 다른 탭으로 넘어가는 순간 뜹니다. 툴바의 "미니 창" 버튼은 없앴습니다. 설정 토글과 같은 걸 두 군데서 켜면 언젠가 둘이 어긋납니다.

카메라 버튼은 이제 트랙을 실제로 멈춥니다. 영상만 숨기면 브라우저 표시등이 켜진 채라 끈 줄 알고 찍히게 됩니다.

PiP은 아직 실기 검증이 안 됐습니다. 프리뷰 창이 카메라를 막아 확인할 수 없었습니다. 크롬에서 세션을 켜고 다른 탭으로 넘어가 확인이 필요합니다. 브라우저가 사용자 제스처 없는 PiP을 막는 경우가 있어, 안 뜨면 그 때문일 가능성이 큽니다.

09 AI 세션 회고 연결 신규

결과 화면 세 문장이 마크업에 박혀 있어, 세션이 뭘 했든 같은 말을 했습니다.

파이프라인은 이미 있습니다

10 서체 정리

세 벌에서 한 벌로.

Wanted Sans · Pretendard · IBM Plex Mono 셋을 쓰고 있었습니다. 지금은 Wanted Sans 한 벌입니다. 공유 카드 캔버스까지 같습니다. 숫자는 서체를 바꾸는 대신 font-variant-numeric: tabular-nums로 폭만 고정합니다 — 25:00 → 24:59로 바뀌어도 자리가 흔들리지 않고, 한글 UI와 숫자의 질감이 끊기지 않습니다.

Geist Mono는 넣지 않았습니다. 모노 서체를 쓰는 진짜 이유는 0/O, 1/l/I 구별인데, 방 코드 알파벳이 이미 그 넷을 빼고 만들어집니다 — ABCDEFGHJKLMNPQRSTUVWXYZ23456789. 헷갈릴 글자가 애초에 나오지 않으므로 여섯 글자를 위해 서체를 한 벌 더 싣는 값이 없습니다. --font-code 토큰은 만들어 뒀으니, 개발자용 ID·디버그 값을 화면에 내놓게 되면 그 한 줄만 바꾸면 됩니다.

11 모드 손보기 신규

모드를 고르는 것과 모드를 손보는 것은 다른 일입니다.

방 만들기 4단계의 모드 카드 우측 상단에 연필이 생겼습니다. 카드를 누르면 고르고, 연필을 누르면 그 모드가 어떻게 동작하는지 바꿉니다. 카드 자체가 <button>이라 안에 연필을 넣으면 버튼 중첩이 됩니다 — 마크업이 깨지고 키보드로 안쪽에 닿지도 않습니다. 한 칸을 감싸 둘을 형제로 뒀습니다.

항목형태이유
음성 안내토글되돌리는 비용 0 → 누르는 즉시 반영
스트레칭 자세앉아서 / 일어나서 / 섞어서같음
이 모드가 보는 것읽기 전용카메라로 기준 맞출 때 정해짐 → 마이페이지 몫

닫을 때 모드 격자만 다시 그립니다. 무대를 통째로 다시 그리면 카드가 다시 날아 들어와서, 연필 한 번 열었다 닫았을 뿐인데 화면이 새로 뜬 것처럼 보입니다.

모드별 차별성 — 제안 (미확정)

모드는 민감도 슬라이더의 대체물입니다(C-04에서 슬라이더를 없앤 결정). 그러니 모드끼리 달라야 할 건 "얼마나 예민한가"가 아니라 "무엇을 정상으로 보는가"입니다.

도서관내 공간팀플내 모드
보는 항목목 전방 · 어깨 높이차 · 숙임각등 젖힘 · 목 전방목 전방 · 좌우 기울기직접
판정 지연길게보통짧게직접
자리 비움엄격관대매우 관대직접
알림무음음성시각만직접
  • 도서관에서 고개 숙임은 정상입니다 → 숙임각을 아예 다르게 봅니다
  • 팀플에서 자리 비움은 정상입니다 → 복귀 후 몇 초는 재지 않습니다
  • 내 공간에서 등받이 기댐은 정상입니다 → 목이 따라 나올 때만 잡습니다

이렇게 하면 "어느 모드가 더 빡세냐"가 아니라 "내 상황이 어디냐"로 고르게 됩니다. 값은 아직 확정 전입니다.

증상진짜 원인

1분 미만 세션이 "1분"과 "0분"을 동시에 표시 큰 숫자와 문장이 각자 반올림했습니다. 1분 미만은 초로 말합니다
우측 상단 톱니바퀴가 반응 없음 핸들러가 없었습니다
라임 배경 위 로고 아이콘이 안 보임 흰 획이 라임 위에서 1.10. 텍스트 대비 검사기가 SVG stroke는 못 잡습니다

제가 만들었다가 고친 것

  • --red-ink를 세션 종료 버튼의 채움으로 썼습니다. 그 토큰은 옅은 바탕 위 글자용이라 다크에서 밝은 쪽으로 뒤집히고, 흰 글자가 2.52가 됩니다.
  • 모션 가드를 추가하면서 기존 것을 못 봤습니다. 담요가 둘이 되어 하나는 죽은 규칙이 됐습니다.
  • 빈 상태 문구에 레퍼런스 앱의 캐릭터 이름이 들어갔습니다. 가져오면 안 되는 것이라 걷어냈습니다.

정리한 것

앱을 감싸던 디자인 설명 문서를 통째로 걷어냈습니다(-3,820자). 오른쪽 아래 "설명 보기" 버튼도 없앴습니다 — 제품이 자기 레이아웃을 설명하겠다고 하지 않습니다. 앱이 곧 페이지입니다. 바탕은 흰색으로 못 박았습니다 (data-theme="light") — 기기가 다크면 반쯤 만든 다크 테마가 나오던 것을 막았습니다.
